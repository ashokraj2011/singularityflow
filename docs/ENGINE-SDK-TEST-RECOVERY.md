# Namespace test recovery and bounded execution

This is an explicit namespace profile for the complete configured test set. It keeps native TRP
records, risk evaluation and installed Git behavior unchanged. It does not claim native selective
test cohorts, baseline-risk waivers, reused evidence or live provider qualification.

## Agreement and command continuity

`test-recovery.context` returns the pinned policy, every phase's actual configured/accepted command
inventory, the previous agreement, an exact context hash and the real human authority groups.
`test-recovery.confirm` records that exact review through the common conditional human-mutation
coordinator. Original receipts, identity, authority, head and configuration are verified again.
Neither an enabled setting nor a supplied readiness flag can substitute for that record.

The agreement runs all configured checks and retains failures. A command amendment still needs its
own independent command decision, a fresh agreement over the changed inventory and a matching
executor. An earlier passing run remains historical; it cannot satisfy a changed draft. Repeated
confirmation cannot reset an unchanged agreement or its repair budget. Publication and downstream
review carry readable, separately versioned agreement evidence. Check-plan v3 binds the actual
agreement; configured-only v1 and command-amended v2 retain their previous meanings.

## Repair execution

The embedding application may bind `NamespaceEngineOptions.repairs` to explicit source-scoped SGOS
Execution Units and an execution owner. `phase.repair.run` selects an actual failed check operation,
authenticates its original draft and source, and derives repair paths from the approved plan. Its
first profile prohibits edits to executable test sources and runs with zero model invocations.
The host's executor must enforce its declared task scope; the SDK independently compares all
selected repository snapshots afterward.

Before execution, SDA conditionally reserves a numbered attempt against the pinned zero-to-three
automatic-attempt limit. The original failed report, plan and command inventory stay retained.
SGOS owns execution, stopping, quiescence and interruption recovery. The SDK then invokes the same
registered `phase.source.retain` and `phase.checks.run` operations for the actual repaired bytes.
Only a real passing retry produces `repaired`; it still needs prepublication and independent phase
approval. A failure stays `repair-required`. An out-of-scope change stays `scope-review-required`,
preserves its actual effects and cannot claim successful test execution.

Every reservation authenticates its previous conditional receipt, including attempts against a
later failed retry. Lost replies are reconciled by the original operation identity. Replaying an
accepted result does not run the executor or tests again and works without local authoring files.
A spent automatic budget offers human source inspection and command review; it never loops by
allocating another operation ID or drops a required check. Agreement evidence also survives actual
amendment, upstream and reviewer returns without a second agreement when the inventory is unchanged.

## Mac qualification and remaining owners

Actual Node test failures and repairs run on filesystem, SQLite and application storage. Tests also
cover successive failures, exhausted budgets, unchanged test files, scope violations, lost reservation
and completion replies, original timeout/permission details, independent publication, command changes
and offline installed/shared-only replay. Native TRP policy, admission, repair and preparation parity
tests remain separate compatibility evidence.

Failed-test risk decisions, approved baseline/cohort selection, reused-evidence decisions and
provider-backed repair profiles still require their own original evidence and authority owners.
Person presence, external design/MCP containment, signing, integrations and application review are
separate contracts; this profile does not replace them with success labels. The active Phase 5/7
completion ledger continues to name the remaining work. Mac-only testing does not qualify Windows
or an external model service.

## Shared narrowed-run values

`testing/recovery` now exports `testNarrowingPolicies`, with explicit text hashing, admitted
record observations and observation time. It owns observed narrowing, agreement exclusions,
fingerprints, extent comparison, eligibility, record/revocation values, expiry and exact decision
bindings. It cannot discover a repository, authenticate a human, execute tests or approve a phase.
The record input requires the actual command and attempt identity; the declaration does not promise
an observation identity omitted by its caller.

The native `test-narrowing.mjs` adapter preserves original signatures, presence-counted records and
optional clock defaults. File and script collection, Git baseline reads, command rendering and
native gate coordination remain there. An expired or revoked record cannot become an active one;
native state evaluation reads the clock only where the original implementation did.
