# Independently inventoried known failures

The namespace SDK has separate `test-risk.known-context` and `test-risk.confirm-known` operations.
They connect the existing pure TRP evaluator to actual accepted SGOS executions and conditional
human receipts. Native Git intake, terminal presence, baseline records and authority remain with
their original adapters. No CLI or Copilot command is invented for these namespace-only operations.

## Exact review and continuation

The context requires the phase ID, an actual baseline check operation and an actual candidate
check operation. It verifies the original accepted `source.bind` receipt for every repository.
The baseline execution must have run on that repository's original pre-feature source revision;
a later failed feature run cannot be relabeled as a baseline.

The approved workflow must enable test recovery, `known-test-failure`, evidence reuse qualification,
the human risk authority and an independent `caseInventory`. This delivery still executes every
configured command. It does not select tests, skip known failures, reuse a receiving execution or
turn failed assertions into passed tests.

The risk adapter supports direct native Node `--test --test-reporter=junit` with explicit files,
the independently pinned `node-test-junit-v1` case inventory and its repository/Node-builtins
dependency declaration. Every expected case must occur exactly once. Missing, extra, duplicate,
skipped, renamed or changed cases cannot qualify. Causes, protected files, runtime, configuration,
environment and command selection remain exact. Only explicitly approved ordinary source roots
can vary; nested tests, fixtures, configuration and non-code resources remain protected.
The current adapter's mutable implementation files are JavaScript, TypeScript, Python and Java
source under those roots. Other files remain protected. Malformed case rows and non-canonical
roots return an explicit policy error before report matching.

`createEnvironmentQualifiedNodeCheckExecutionUnit` is an opt-in SGOS profile. It captures the real
executor platform, architecture, native Node binary digest, command environment and reporter root.
It verifies the executable before execution. The old local-check constructor/profile stays v1.
Historical report paths are interpreted using their original path grammar; replay does not read
the previous laptop's filesystem.
The qualified constructor validates plain options and nested command data before filesystem
access. Caller-provided environment qualifications and accessor-backed inputs cannot become
executor facts. Missing executable paths retain their actual filesystem error.

The human confirms the returned context digest, expiry, reason, follow-up owner and remediation
reference. The original pinned group authenticates that decision; a request cannot provide
`approved`, an identity, a test outcome or an authority receipt. Duplicate decisions are refused.
An acknowledgement lost after conditional acceptance replays the original receipt.
The full review packet is immutable evidence referenced by a compact decision record. Reading
context does not write it; the conditional decision writer retains the exact reviewed packet.

After review, authoring rebases the preserved private draft to the actual current shared revision,
retains current source and executes fresh checks. Existing acceptance tests can be proposed only
when their exact source and real executions appear in the reviewed baseline/candidate context.
They still need their approved plan bindings, current successful acceptance witnesses and every
configured visual or inspection witness. No cosmetic test edit or invented reviewer return is used.
New executable tests can be admitted separately when they are absent from the original baseline,
allocated by the actual approved plan and observed passing in the current configured execution.
The human reviews their exact file digests, command and case inventory. A new or changed test
input needs a fresh context and decision; modifications to existing assertions remain protected.
Completion order and the reader laptop's locale cannot change test identities or review hashes.

## Evidence and current permission

The new record family is `sflow-namespace-known-test-run-risk/v1`; publication retains
`known-test-risk/v1`. Code policy v33 separates this permission from the original Code profiles
and Code environment-risk v32. Its execution exception explicitly states `testsPassed: false`
and `failedAcceptanceWaived: false`. The full run and every failed case remain retained.

The original full-command recovery agreement does not itself waive failures. The additional known
failure decision is an explicit, separately authenticated exception with its own wire and owner.
Normal phase submission, human approval and independent-review policy still apply.

Publication, submission, approval and final Story evidence reconstruct the actual original source,
run and human decision. Expiry and revocation expose the original owner's review/renewal route;
renewal does not rewrite a publication or an approval. Evidence age is a separate pinned limit.
Renewing a human permission cannot make an old execution fresh. A changed assertion, new failure,
different environment or protected dependency requires repair or a genuinely qualified new baseline,
followed by execution. Error identity, missing paths and timeout details remain intact.

The registered decision list exposes the original known-failure review. Final evidence records the
exception separately from actual acceptance results. A shared-only consumer can replay the original
decision and approval after removing the local checkout and private working store.

## Downstream Verification and Release

Code input policy v2 (`approved-code-inputs/v2`) carries an approved Code v33 producer's actual
test counts, failed cases, original human risk and retained execution references. Passing-only
Code input v1 and its original bytes remain unchanged. An environment-risk publication is not
silently admitted by the known-failure profile.

The consuming phase does not execute or claim another run. Its current permission and source
inventory are checked before publication. Expiry exposes renewal at the original producer; the
consumer can continue its preserved draft after that decision. A changed source still requires
genuine producer revalidation. Code policy v33 separately requires passing Story acceptance
witnesses, including any configured visual or inspection obligations.

Conformance v3 explicitly discloses inherited known failures; v4 combines that disclosure with
the existing upstream-issue association. Original conformance v1/v2 keep their meanings. A
matched Story clause does not claim that the unrelated failed tests passed. Final evidence
continues to evaluate the original owner's current permission without rewriting earlier approvals.

## Shared native values

The original baseline-risk constructor now lives inside `testRecoveryPolicies` and requires an
explicit admitted time. Its native wrapper still supplies the clock and retains terminal consent,
Git verification and durable authority. Twenty-four independent outcomes were captured from the
original constructor at `b1a77c07845ebcb7fa75c5ace22b4bdfeb6eb493` before extraction; values, seals,
normalization and errors are compared against that capture. A constructed record is not a human
receipt and cannot authorize the TRP gate.

## Remaining work

Independent selective execution and environment-sensitive cross-execution reuse still need their
own execution/selection owners. This delivery requires an actual same-phase pre-feature run; it
does not create a baseline for a future phase by changing an earlier run's phase ID. General
baseline execution across future phases remains separate. Live application review/comparison,
the remaining external evidence/execution owners and the other completion-ledger items remain
required before Phases 5 and 7 can be marked complete.

actual Node failures and passing acceptance tests, independent human decisions, renewed and revoked
permissions, newly added tests, Code-to-Verification-to-Release evidence, protected-source changes,

72-stage installed conformance, repair, human-return, partial-decision, upstream-return and
multiple-Code compatibility tests also pass. Repeated runs are counted once.

The new installed offline consumer completes its real Code, Verification and Release journey
with an empty PATH, native Git/CLI/state imports denied, actual human approval, deleted-checkout
replay and strict NodeNext typing. Its final run passes in 55.5 seconds. The unchanged original
34-test package qualifier is run alone within its original 120-second parent and 60-second child
limits. Source validation, VS Code types, the Git ownership audit and all 13 unchanged bundle

Windows, hosted CI, live models, production installation and merging main are outside this
extraction. Phases 5 and 7 remain open for the owners in the active completion ledger.
