# Namespace decisions, original evidence and recovery

This delivery continues Phases 5 and 7 on `codex/engine-sdk-foundation`. It does not migrate
installed projects, change Git authority, or complete the remaining policy/execution owners in
[the completion ledger](ENGINE-SDK-PHASE-5-7-CLOSURE.md).

## Boundaries

The kernel now owns scope statements and inventory, scope/completeness/applicability decisions,
plan accounting, obligation-risk rules, upstream issue records and test-recovery schemas/evaluation.
Native wrappers retain their presence-aware reads, digest/path bindings, command guidance and
existing records. Optional SDK `/scope` and `/testing/recovery` exports accept explicit immutable
capabilities; importing them performs no filesystem, Git, provider or process discovery.

Namespace human mutations share one conditional writer and a separate receipt reader. Each owner
recomputes the original source, pinned authority and transition. Explicit operation IDs distinguish
an identical retry from a new decision. Preparation and acceptance retain their actual errors;
an unknown acknowledgement is reconciled against its original transaction.

## Scope and local inputs

`scope.context`, `decision.scope`, `decision.completeness` and `decision.applicability` use original
Story bytes, verified published definitions and accepted human clarification records. A current
private specification can supply its actual clauses before publication. A decision over that draft
retains the reviewed specification bytes and a separately versioned source binding. Before accepting
a prepared decision, the owner checks that the draft still matches. Historical accepted decisions
replay from shared evidence without requiring the original laptop.

`story.document.attach` and `story.document.detach` retain input metadata through registered
transactions. Document and image content remains in the explicitly supplied device-local store.
The shared Story carries content hashes, sizes, names, media types and identities. Preparation can
use an input store separate from its private draft store. Detachment preserves old bytes and receipts.

All phases receive attached inputs through resource manifests. Another device without the matching
originals receives a v3 entry manifest naming the missing document IDs and expected hashes, with a
re-upload/read recovery action. Earlier v1/v2 entry contracts retain their meanings. A successful
metadata operation never claims document upload, application changes or phase approval.

## Original upstream ownership

`upstream.raise`, `upstream.decide` (accept-risk/dismiss) and `upstream.list` authenticate their
producer publications and original decisions. Read-only upstream proof does not import a writer.
The producer's retained test proof is included when the issue is about Code.

Conformance v2 links an authored partial verdict to a retained upstream issue and its original
owner. Association requires the exact clause or an exact filed discrepancy covering it; merely
naming an unrelated UPI cannot carry its decision. One original accepted upstream decision covers
all genuinely linked rows. Context offers `upstream.decide`, and a duplicate `conformance.decide`
for that link is refused with the original issue route. Expiry remains effective. Neither the
observed verdict nor the upstream artifact is rewritten. Existing conformance v1 bytes replay
under their original rules.

Artifact-derived issue filing, return/amend/plan-correction outcomes and forward amendments still
need their remaining namespace owners; their explicit refusals remain in place.

## Code returns and first execution

Code history now authenticates actual human route-choice returns and unchanged revalidation.
The latter requires a fresh test execution for the new generation; an earlier passing run does
not satisfy it. This adds Code v4 without changing v1-v3.

A first Code generation after an earlier phase was returned uses Code v5. It verifies the accepted
return and the exact independent human approval resolving it. Copied change-request fields and
invented resolution generations are rejected. Original publications, source/test evidence and
human approvals remain immutable. Targeted/surgical repair and other unbound Code owners remain
explicit remaining work.

## Plan accounting and open Code continuation

`decision.plan` now authenticates original approved planning inputs and additive human accounting.
It retains observed source snapshots and exact file hashes, refuses changed source before acceptance,
and replays without the original device. Code v6 carries those original decision receipts and rejects
a file changed after its latest accounting. Qualified repository roots keep each supporting path in
its reviewed repository. A later, unapproved planning owner is not treated as an input to this decision.
Plan row/evidence corrections retain their separate remaining owners.

Code generation v2 preserves a genuinely open generation after an explicit digest-bound private rebind.
It carries the original private draft/intent metadata and authenticates the earlier accepted lifecycle
basis. It retains the original source selection and checks current source again before saving. A race
preserves the previous private head. Nested continuations replay from shared source evidence without
the former checkout. Ordinary generation v1 and Code v1-v5 records keep their original meanings.
Permission and timeout failures reading a predecessor remain their actual failures, rather than
being relabelled as record corruption.

## Bounded read reuse and package qualification

Immutable record, content and original Story/configuration proof reuse lasts for one awaited
registered operation, bounded to 256 entries and 8 MiB. Returned values are independent copies.
Transaction boundaries clear this reuse, including failed or lost write acknowledgements, so
post-acceptance read errors remain observable. No advisory cache or reusable readiness flag
authorizes a mutation. Mutable heads, authority,
identity, permissions, private drafts and live source admission retain their fresh checks.
Standalone preparation/publication/submission/approval hosts use the same invocation boundary.

Read-only Auto Plan and skill-package inventory no longer load synthesis/provider execution.
The existing gateway module ceiling is unchanged. The original installed-package qualifier passed
all 34 checks in 104 seconds on this Mac, with its unchanged 120-second parent and 60-second child
limits, without skips. The new value exports also pass offline installation and NodeNext checks.
This is a local qualification result, not a matched before/after product-latency benchmark.

Functional Mac checks cover all three storage backends for linked upstream/conformance decisions,
local document/image takeover, scope/completeness/applicability and receipt replay. Additional
checks exercise a changed draft after interrupted preparation, a lost attachment acknowledgement,
separate private stores, first Code after a reviewer return, actual test revalidation, and preservation
of real errors after accepted effects. Final gate results are recorded separately; no Windows,
hosted CI, live provider, real Story, installed authority or main merge is part of this delivery.
