# Application-review values

Application-review event hashing, event-chain validation, finding lineage, consumed repair counts,
state projection, confirmation rules, report pagination and capture-set checks now have one pure
kernel owner. The native `application-review-contract` module binds the same byte/hash primitives
and re-exports the original vocabulary. Native application startup, browser capture, evidence
retention, human identity, signed presence and decision transactions keep their original owners.

The opt-in `@singularity-flow/engine-sdk/application-review` export provides
`applicationReviewPolicies(recordBytes, digests)` and strict NodeNext declarations. Its
`sflow-application-review-values/v1` describes value rules. It persists no session, launches no
application, captures no image and authenticates no person or decision. Observation facts passed
to a pure completion calculation must already have been established by their owning adapter.
The factory offers no execution or approval method, and an injected record-admission callback
is rejected: only the existing frozen UTF-8 byte and SHA-256 primitives are accepted.

## Unchanged records and errors

Foundation now declares the original application-review-session v1 family metadata, including
its required numeric version and mutable session envelope. The native migration registry uses
that same metadata. Policy v1, events, original event hashes, exact action replay, confirmation
checks, findings, capture receipts and all native error codes/messages retain their meanings.
Duplicate findings still share their root's consumed repair count; a passing test or model repair
claim cannot replace the person's actual recheck or acceptance.

Eighty-five outcomes were captured from the original `29a9e6f11` contract, SHA-256
`20ddee9768a7a7c2561194071b3d14822acb9f5038442d83fc462a42563f8ab3`, before extraction.
The JSON oracle explicitly encodes native in-memory undefined fields rather than dropping them.
Both native and portable owners reproduce every captured result and exact failure. These are
value fixtures; they do not assert genuine image, execution or human-authority evidence.

The earlier policy suite's old reader-body fingerprint omitted the already-delivered shared
`recordReadTargetVersion` expression. Its test now permits exactly that one substitution while
keeping the original fingerprint and checking migrate-on-read and preserve-versions behavior.
The native reader body itself is unchanged by this extraction.
