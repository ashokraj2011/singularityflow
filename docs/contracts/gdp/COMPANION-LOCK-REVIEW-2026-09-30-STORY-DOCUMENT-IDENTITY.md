A v3 catalog is refused by a build that knows only v2. That is how every schema step in this registry behaves, and the release notes say so: everyone on a team must upgrade before one of them writes names or phases. The v3 fields add no authority. A name is only a label that lookups resolve after IDs and aliases. `phases` only narrows which prompts a document is offered to, and narrowing a phase that already used a document goes through `documents scope`. That command records a `document-scope-decision`, marks only that phase's prompt receipts stale, and reopens the earliest phase affected, exactly as detaching evidence does. The governance gate refuses a catalog with a missing or duplicate name, or a phase the Story does not have. All digests were computed from the file bytes at the previous review, at `main` and in the patch, not copied from a failing assertion.
