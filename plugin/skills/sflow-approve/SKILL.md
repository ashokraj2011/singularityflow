<!-- sflow-output-contract: governed-review -->
**Output contract:** Require human review of exact bound documents outside chat; refresh packet and explicit consent. Summarize artifacts with verified Markdown-preview links; never paste document bodies, code or diffs into Copilot. For code, list touched paths and observed added/deleted/created line counts; unavailable stays unavailable. Use existing evidence, not extra calls solely for display. Summaries, links and opened previews are not human review or approval. After a blank line, display each next action as three separate Markdown bullets, in order: "- Copilot: `<copilotCommand>`", "- Shell: `<command>`", "- VS Code (model-free): `<modelFreeCommand>`". Preserve exact returned routes; never combine them on one line or in a table. Missing Copilot: "no verified equivalent"; missing Shell or model-free: "not available for this action". Never invent routes or make further calls for formatting. Run a check only when a returned field or command asks for it; never decide from a step's name, kind or route that it applies. A refusal saying a check does not apply to this step is not a blocker: skip it and continue. Act on a result's `act` first: its state, `do` routes and any `ask`. A bounded result names `agentOutput.read` ranges and `omittedFields` text files; read all in one response with your file tool. If your host saved a result to a file you cannot open, run that command again with `--for-agent --json`; never read the host's copy with shell tools.
<!-- sflow-execution-boundary -->
**Boundary:** reuse entry `ready`/`workId`, cwd=`repositoryPath`, or as is from a non-Git (chat) folder: SFlow finds the bound checkout; never refuse or wrap for it; CLI/`workItemRoot` paths only; never `$HOME`. No duplicate lookup. Use exact CLI-returned paths. `repositoryPath` is command cwd, not a prefix for absolute file paths. Never rebase paths or strip `.git/worktrees`. Issued private/external files are exact exceptions to repository confinement, not wider read/write permission; writes still need authorization. Resolve relative paths only against their declared base. On failure, preserve the path and error; never search or recreate it.

<!-- sflow-turn-boundary: approval-only -->
**Approval-only:** An explicit human phase ID confirms only the unchanged packet already reviewed in this conversation. The approval CLI is the sole permitted lifecycle mutation, besides /sf-decide step 14 for the decision list. Never edit repository files, run tests/builds/raw Git, delegate, submit, or begin/author another phase. A failed approval ends this turn.

1. A positional argument selects **PHASE-ID**, never Work ID. Run `singularity-flow choices begin approve <WORK-ID> --fetch --for-agent --json --review-packet`; on `approvalPacket.readiness` `terminal-obligations-required`, relay blockers/actions and stop without choices or generic recovery. On `decisions-required`, load /sf-decide and do its steps 11-14 in this turn; never print raw decision commands. Require the supplied phase to match.
2. `approvalPacket.review` is `singularity-flow phase show <phase> --for-agent --json`. Match receipt, `reviewBinding`, artifacts and briefs to `approvalContext`; mismatch or missing binding stops. Do not repeat document lookup.
3. **Review outside chat against the exact binding.** List each artifact/brief's identity, generation/hash and verified Markdown-preview link; binary: metadata/path. Require human review of complete bound documents; never infer it from opened previews. Reuse same-chat human acknowledgement only for an exactly matching non-null `displayBinding` and unchanged `reviewBinding`. New chat, changed/null binding, omissions or truncation require fresh human review. Tool output or summaries are not review. Show current `reviewBinding`; document reuse never reuses approval consent.
4. Show identity/authority, agent, checks/usage, decisions/`owedDecisions`/self-approval warnings and `approvalCheck`/`blockingCommits` (advisory: show them, then continue). Unauthorized: show its approval groups (`/sf-approvals`) so an authorized approver uses `/sf-inbox`; stop.
5. A human `/sf-approve <PHASE-ID>` or exact phase answer **after** complete review of this exact `reviewBinding` is `<TYPED-PHASE>`: do not ask again. Otherwise ask for the exact phase ID to confirm linked-document review and approval; wait. A phase supplied before a new or changed packet review is not its confirmation, even if document bodies match. Run `singularity-flow choices answer <TOKEN> phase-confirmation <TYPED-PHASE> --json`, then `singularity-flow approve <TYPED-PHASE> --work-id <WORK-ID> --fetch --selection-receipt <TOKEN> --for-agent --json` only when `ready: true`. When the packet review's `approvalChecklist` lists articles, ask for one answer per article (satisfied, exception or not-applicable, with a reason for the last two) with the confirmation and add `--article <ID>=<DECISION>` per article, then `--article-reason "<REASON>"` in the same order. From /sf-decide 14, add its `withApproval.flags` (decisions in this commit). Never add `--yes`; the receipt is consumed once. `--for-agent` grants no authority.
6. Refusal: relay, end turn (one routed to `singularity-flow decisions <WORK-ID>`: load /sf-decide steps 11-14 now instead); `PHASE_ALREADY_APPROVED`: offer `/sf-next`. Never `--allow-dirty`. Success: commit/push, authority/self-approval. Relay `contextBoundary` commands in order (`/clear` or `/compact`, then `/sf-next`); `keep`: next turn. The approval CLI advances and activates the next phase when the threshold is met; no second advance. End this turn before next-phase authoring.

TRP: read and follow `singularity-flow explain test-recovery`; returned legal actions only.
