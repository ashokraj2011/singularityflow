# Multiple independently approved Code phases

A later Code phase can carry earlier observed claims only from the original publication,
submission, retained source, pinned execution and actual human approval. The read-only
`namespace-code-predecessors` owner reconstructs those proofs through SDA ports. It does not
accept a caller's coverage flags or scan branches, history or a previous developer's checkout.
Each phase still retains its own current source and executes its own pinned commands.

## Separate evidence contracts

`sflow-namespace-source-generation/v3` opens the first generation of a later Code phase against
the latest approved Code snapshot for each selected repository. It preserves the original Story
baseline for cumulative accounting. Its predecessor proof binds the original accepted lifecycle
basis and can be checked from shared records after the source checkout is removed. Existing
generation v1/v2 records keep their original interpretation; same-generation continuation still
uses v2 with its exact original intent.

Code policy v10 retains the earlier approved observations and all of their provenance references.
Code policy v11 adds the existing independently authorized, exact-candidate human acceptance
contract. Original Code v1–v9 records and native Git behavior remain unchanged. A visual decision
from another candidate is not a substitute, and a previous test run is never relabelled as a
current-phase execution.

The reader projects approved plans and additive decisions through each repository's actual
planning roots before combining their claims. An allowed frontend path cannot account for a
backend change. New source and test files allocated to the current phase are accounted for by
that phase's own candidate and checks.

## Conservative reuse and recovery

This initial profile requires every previously archived application input to remain exact,
including its content, role and executable mode. A previously approved removal must remain
absent. A later phase cannot silently carry old claims after changing one of those inputs,
even if its own focused tests pass. The refusal identifies the original producer and changed
paths and provides the registered `upstream.raise` action for actual owner revalidation.
Restoring the original input also requires retaining and testing the current candidate again.

This is an explicit conservative boundary rather than a dependency-graph or semantic equivalence
claim. Targeted repair and narrower dependency-aware reuse remain separate completion work.
Changes do not rewrite old publications, reset unrelated approvals or upload local attachments.

Repeated immutable predecessor proofs share a bounded invocation-local memo over the exact
record/content ports and complete workflow/current-source identities. The memo expires at every
transaction boundary, including a failed or uncertain write. It does not cache errors, current
source admission or final human authority.
