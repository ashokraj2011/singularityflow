PART I — WHY

1. Business overview

AI agents now draft code faster than any review culture can absorb, and the organization is offered a false choice: agent autonomy or formal control. Choose autonomy and weekend POCs cement architecture and ship regressions; choose control and developers route around governance, which then reports green. SingularityFlow is the PDLC Assistant — the workflow tool for the product delivery lifecycle — built on an core engine for changes produced by humans or agents: the same standard of proof for every change, with ceremony removed rather than governance removed. It runs inside tools already owned (VS Code, Copilot, Jira, Jenkins, Git); it procures nothing and hosts nothing. Positioning: the PDLC Assist Extension in the target architecture; the future control plane subscribes to its events.

AudienceWhat changes for them
DevelopersAI does the drafting; checks run in under a second on the exact bytes; the governed path is also the shorter one
Product owners / PMsstatus computed from the work, not reported; requirement changes show what they reopen
Architecture / risk / QAapprovals bound to exact versions; evidence written as a by-product; audit from a bare clone
Leadershipmeasured review time, rework, defects traced — never "governance records produced"

2. Why it makes coding at scale less error-prone

Errors at scale are binding failures, not typing failures: code that compiles and passes tests but is attached to no requirement, no boundary, no approval, no evidence. The core engine binds five things mechanically — intent (numbered clauses), context (a computed world model, not a prompt pile), permission (exact scope and protected paths), conformance (deterministic checks on structure, tests, coverage), and record (receipts, refusals with the fix named). Measured on the platform's own ledger: an agent that tried to edit the workflow file that judged it was refused (protected path); a passing test report bound to a previous test body would be refused (test-identity evidence, proposed). Every claim on this page is labeled; the platform publishes its own gap register.

4b. How documents and code are checked

The rule is simple: The AI produces drafts; the checks that decide are computed, not asked of the AI. Every artifact — a specification, a plan, an implementation summary, test evidence, and the code itself — passes through checks that run without any model. The AI helps produce the content; it is never consulted about whether the content is acceptable.

What is checkedWithout AI (the checks that decide)With AI (help that never decides)
Intent (story source)Pinned immutably at start with a hash; any later artifact that contradicts it is stopped and routed to an intent amendment.The AI drafts questions to clarify it; a human answers; answers are pinned.
SpecificationRequired headings present; minimum authored content; no TODO or placeholder left; every requirement and acceptance criterion has a stable id in the right syntax; unresolved clarification markers block publication; cited constitution articles must exist at the pinned revision.The AI writes the draft from the pinned intent and the repository map; a product approver signs the exact version.
PlanEvery clause has a test-strategy row with exact repository paths (directories or prose are refused); expected paths recorded; the plan cites the clauses it serves.The AI proposes approach and sequencing; an architecture reviewer signs.
CodeParsed by built-in extractors: claimed functions and files exist; claimed tests reference the claimed code; changes stay inside the story's write scope; protected paths force a named human; per-capability structural rules (layering, tagging) hold.The AI drafts the code inside an isolated candidate; it may read the parsed map on demand.
Tests and evidenceConfigured commands run on the frozen candidate; exit codes and reports are hash-bound to that exact version; a skipped test is a failure; evidence from another version is refused; (proposed) each acceptance criterion binds to a named test whose body hash must match.The AI writes tests and reports results — its report is advisory; only the recorded run counts.
Coverage of requirementsSet arithmetic: required clauses must be a subset of claimed clauses; missing claims are named.The AI attaches claim tags; the core engine counts them.
ApprovalsSignature verified over the artifact hash, by a member of the required group, not the author; edit one byte and the approval is STALE with the cause named.None — approval is a human act; the AI cannot request, grant or simulate it.
PublicationAll of the above re-checked at the moment of publishing; atomic advance; receipt written; audit can re-run every check later from a bare clone.None.

5. Repository model (world model) and code parsing

SingularityFlow can build a repository model from code, publish the validated current projection to the repository's configured state branch, and reuse it across stories and machines that resolve the same complete governed identity (source, scope, registries, contracts, budgets, and execution profile). Existing legacy-v3 and registered-v4 builders are operational. A separate WMP increment is adding immutable exact-key model/view history so an earlier binding can be found after the current projection moves; that newer optimization is not yet connected to normal Story preparation. The model is organised in three parts:

PartWhat it isHow it is kept honest
FactsA ledger of facts extracted from the code — files, symbols, signatures, imports and dependency edges, interfaces and schema contracts, test identities — each with its source, its extractor version and a derivation recordEvery fact carries an origin class (parsed, declared, signed, computed), a status (available, partial, unavailable, contradicted) and an assurance level; absence is recorded as a fact, never skipped. No AI is used to produce facts.
ViewsThe operational WMB v4 catalog contains four registered views: dev.impact, dev.hotspots, biz.rules, and arch.contracts. Five additional model-free WMP overview contracts and pure renderers exist as code-local foundations; normal WMB/Story execution does not yet emit, consume, or replay their persisted view bindings.A registered view can only use admitted facts under its contract. Deterministic renderers add no model claims; an explicitly permitted semantic composer remains bounded, validated, and advisory.
ProjectionsExports in external formats — today FINOS CALM for the architecture — generated from the fact ledger and the capability mapEach element is labelled with its provenance (source-exact, structurally-derived, deterministically-derived, human-confirmed, runtime-observed, not-applicable); heuristic or model-advisory content is forbidden; no AI is used.

Where it lives and who is the authority. Current World-Model publication writes a manifest-registered set of files to the configured state branch under the existing WMB transaction and authority rules, with staleness receipts that name what changed (source snapshot, scope, capability snapshot). A local cache and model-free query index speed reads; both are rebuildable and never authoritative. The additive singularity/world-model-history contracts and read-only inspection foundation exist, but the new build-to-binding path does not yet emit or reuse those immutable entries through normal Story/WMB execution.

What the AI sees. When verified grounding is available, a story's brief carries the relevant bounded facts and view sections with manifest/hash provenance. When it is unavailable under the shipped worldModel.grounding: warn policy, the phase records a stable unavailable receipt, injects zero World-Model bytes, and ordinary repository access continues. grounding: enforce changes the treatment of consumed-context integrity failures, not availability; a separately required projection or persisted domain may retain its own explicit policy.

Status. Existing legacy-v3 and registered-v4 build/read paths, fact extraction, registered views and projections, CALM projection, current state-branch publication, and existing reuse mechanisms are operational. The WMP governed identity, exact-key lookup, build-to-binding staging, history readers, and deterministic view foundation are implemented but not automatically activated by Story start or grounding. No existing Story or World-Model workflow is disabled by that staged boundary. See the operational WMB v4 guide, the WMP exact-history rollout boundary, and the cross-product roadmap.

PART IV — PLATFORM

13. Infrastructure and deployment

Node 20+ CLI via Artifactory (five small runtime packages — YAML parsing, schema validation, agent protocol SDK, CALM validator — bundled into an offline release closure that CI verifies against exact lock files; no services, no daemon); VS Code extension via internal marketplace; no services, no accounts, no hosted component. Works offline. Existing CI may run sflow verify --json as an evidence provider only; no CI system is required. Upgrade/rollback: readers honor previous schema versions (migration goldens); rollback = reinstall prior package, records unaffected. Corporate-machine hardening (proxy, certificates, Git Credential Manager, cancellation, clone) verified before GA; git is accessed through one layer that resolves the executable once, normalizes paths, batches reads and is tested on Linux, macOS and Windows; accelerators (fsmonitor, untracked cache) opt-in per repository with compatibility checks. Being down stops nothing.

15. Extensibility and future control-plane integration

Everything pluggable is a hash-pinned file: engines (models), units (approved assistant loops or native execution), roles (persona + skills + rules), packs (roles + law), templates, workflows, MCP connectors under core engine-issued permissions. Integration contracts: Jira in/out, Jenkins evidence in, Confluence/SharePoint out, registered event vocabulary with versioned schemas and idempotent outbox to the data lake. The future PDLC control plane subscribes to events and pushes pinned policy; it is never authoritative — delete it and every verdict still resolves from a clone. CALM: generated as a view from governed truth (enforced vs descriptive annotated), round-trip lossless.
