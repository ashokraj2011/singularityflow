# Artifact-member and document-only repair

A human reviewer can return exact members of a published output bundle through `phase.reject`.
The namespace Engine authenticates the original submission, target publication and actual reviewer
authority before selecting those members. The return opens a separately versioned successor;
it does not change the original approval, widen application scope or consume another attempt on retry.

## Ownership and compatibility

The kernel owns member selection, actual before/after comparisons and application-delta admission.
SDK operations coordinate the existing registry path. Read-only owners authenticate original
publication, return and reset receipts. SDA retains conditional records; SGOS executes fresh checks.
Native Git comparison, rejection records, output strings and installed authority retain their
original path. Captured pre-extraction values cover the native bundle comparison.

| Record or manifest | New meaning |
| --- | --- |
| Human decision v4 | Member-targeted return over the original submitted or approved bundle |
| Private preparation payload v4 | Copied predecessor outputs with authenticated repair scope |
| Artifact-set manifest/report v2 | Actual requested, incidental and unchanged member comparison |
| Phase entry manifest v5 | Exact member scope and readable original provenance resources |
| Code history v9 | Document-only return with no application delta |
| Code policy/report v20/v21 | Document-only Code repair, optionally with human acceptance |
| Code policy/report v22/v23 | Document-only repair with repository-local clause coverage |

Earlier records retain their original profiles. Code returns selecting both clauses and members
continue enforcing the clause-targeted application scope. Schema selection stays in the shared
record-schema owner; storage and entry adapters do not branch on wire versions.

## Repair flow

Read the actual submitted packet with `phase.review`, then pass its digest, target phase, exact
member selectors and human reason to `phase.reject`. The public request retains the caller's
declared relative or project-relative aliases. The internal scope contains only canonical members
of the target's retained bundle. Unknown members, arbitrary children of collections, traversal
and wildcard paths are refused.

`phase.enter` issues the repair scope and original return, publication and bundle references.
Read them through the exact manifest/resource IDs. A changed draft, Story or permission invalidates
that read plan; real permission and deadline errors remain intact.

`phase.prepare` copies every retained predecessor member into the new laptop's private draft
store. It preserves the prior private draft rather than overwriting it. Repeated preparation
reuses that successor. The author can correct requested members and records incidental document
changes through the actual comparison; unchanged requests are disclosed rather than fabricated
as edits. Collection comparisons use real file deltas and do not count an overlapping parent
declaration as a second incidental file.

A document-only Code return cannot edit application files. The Engine checks retained source
before starting the successor's checks, then checks the captured source again. Unchanged
application code still executes fresh tests. Mixed visual acceptance still requires a new
candidate-bound human decision; an earlier witness is not borrowed.

Publication consumes the repair marker and retains the comparison with the successor bundle.
Later phases read their own approved inputs. An earlier document repair cannot restrict later
application work. Repeated member returns authenticate every original open request and select
the actual current return; final approval resolves those requests without inventing another
reset or replacing historical proof.
