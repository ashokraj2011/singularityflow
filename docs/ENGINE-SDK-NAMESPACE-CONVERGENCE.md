# Deterministic convergence through the namespace Engine

Convergence now reads actual approved Code publications, their submitted test evidence, original
human approvals and the approved repository plan. It produces one deterministic projection and
retains human judgments separately. A computed fact never becomes a human decision or acceptance.

This is an explicit namespace application profile. Installed Git record formats, hashes, command
output and authority remain unchanged. Native reads use the same pure convergence rules through
a compatibility binding; source access, native schema migration and shell guidance stay outside
those rules.

## Boundaries and versions

| Owner | Responsibility |
| --- | --- |
| Kernel | Facts, settlement, human-answer rules, projection, canonical artifact and confirmation values |
| SDK registry | Context, adjudication, preparation, publication, advancement and submission coordination |
| Namespace readers | Original Code, plan, execution, human receipts and publication proof |
| SDA | Immutable projection/report bytes, conditional Story revisions and operation receipts |
| SGOS | The actual Code executions; convergence does not invent or repeat their test runs |
| Host | Human interaction, prompting and presentation of structured actions |

The native value profile preserves its schema-v6 output and historical v4/v5 seals. A separate
namespace value profile qualifies fact identities with the actual repository ID. Namespace
projection, policy, report, adjudication and confirmation records have explicit v1 contracts.
Private prepared payload v3 retains the kernel projection; original private v1/v2 records retain
their meanings. Submission packet v5 binds the exact confirmed publication and projection;
packets v1–v4 remain unchanged.

## Actual input provenance

Each Code input must have its real publication, submitted packet, policy/report, original approvals,
source archives and independently approved plan. All earlier Code phases retain their own evidence.
The reader derives repository-local clause views from those plans, preserves globally unassigned
clauses and authenticates plan settlement before a supporting path can stop asking a human.

The projection contains namespace references and input digests. It does not invent Git commits,
branch names or laptop paths. A late plan change or changed application checkout retains an explicit
owner-revalidation route. Publication and submission capture current source again; a preview is
not the final freshness check.

## Human judgments and real repair

Use `convergence.context` to read the bound projection and actual input-review operations. Then use
`convergence.adjudicate` with an explicit operation ID, finding ID, disposition and the exact returned
context digest. Identity and authority come from the access port and pinned approval groups.
The request cannot supply an actor or a successful review flag.

Replacing an answer retains the previous answer. Chronological replay checks its original accepted
receipt and input basis. It retains only already-verified history in one bounded read traversal;
it does not trust a copied state flag or rescan application branches.

A blocking rework judgment offers an issue against the real Code producer. An intent judgment
offers the actual approved specification owner. Multiple possible owners require an explicit
selection. Raising an issue grants neither a return nor new authority: the existing upstream
decision still enforces its pinned owner, permitted route and repair budget.

After an actual Code return, the replacement needs fresh execution and independent approval.
Earlier convergence judgments stay bound to their original input basis. They cannot silently
dispose of new evidence. A path a human sent back remains theirs to judge again, even if the plan
previously listed it as supporting work. The convergence iteration can advance while its first
publication generation is still pending.

## Preparation, publication and continuation

`phase.prepare` renders the current canonical projection into the private working store. Repeating
an unchanged preparation reuses that draft. After real input or human-answer changes, deterministic
preparation preserves the previous private draft and regenerates the kernel-owned body. Ordinary
draft writing cannot replace that body.

`phase.draft-check` and `phase.prepublish` inspect the actual projection. Human findings remain
human-review findings. The context offers preparation, then publication, then explicit advancement;
`story.next` points to this context while the generation remains unpublished. These reads neither
stage a report nor grant mutation authority.

`convergence.advance` first returns the exact published review digest. Supplying that digest delegates
through the registered confirmed-submission operation. Submission verifies the actual projection,
human identity, current source and conditional Story basis again, then retains its confirmation in
packet v5. An ordinary phase submission cannot acquire convergence authority from a caller flag.
Independent phase approval remains a separate operation over the retained submission.

Lost acknowledgements resume the original accepted operation. Replays do not create another human
answer, submission, timestamp, test execution or repair attempt. Missing content, original permission
errors and storage deadlines remain explicit failures; no file fallback recreates a Story.

## SDK use and qualification

The optional `convergence` SDK export exposes pure value factories and types. It does not authenticate
their inputs, read a repository, retain evidence or authorize advancement. Applications execute
business operations through `engine.run` and the single registry.

Qualification uses isolated Mac fixtures with real source changes and Node executions, independent
human identities, filesystem/SQLite/application stores, interrupted transactions and source-free
replay. An offline installed consumer verifies process restart, confirmation, independent approval
and shared-only replay. Final passing counts and original package/bundle limits are recorded in
[the completion ledger](ENGINE-SDK-PHASE-5-7-CLOSURE.md). This slice passes 356 distinct affected
Mac checks, including all 98 architecture checks and the unchanged 34-check installed-package
qualifier, run alone in 83 seconds within its original 120/60-second limits. Source validation
passes 4,273 checks; VS Code types, the unchanged Git audit and all 13 original bundle budgets
pass. The gateway remains 851 modules against the unchanged 852 limit.

The two-repository journey combines three independently approved Code producers with confirmed
convergence submission and shared-only replay. Actual Code repair, fresh execution, a replacement
approval and renewed convergence judgment run on all three storage backends. Native compatibility
qualification includes captured v6 values, historical seals, exact failures and real CLI parity.
There are no Windows, live-model, production-Story or installation runs in this delivery.

Artifact-member repair, late plan revalidation, forward amendments, test-recovery agreements,
remaining risk decisions and the other execution/evidence owners stay open in that ledger. This
delivery alone does not complete Phase 5 or 7, migrate an installed project, or change Git authority.
