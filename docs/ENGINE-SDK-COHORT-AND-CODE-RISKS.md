# Observed cohorts and Code environment risks

The opt-in namespace Engine now records observed-suite baselines/cohorts, Code environment risks
and explicit recovery-agreement risk decisions through the registry. Native Git operations,
records, hashes, authority and default evidence profiles keep their original meanings. This
delivery does not complete every remaining Phase 5/7 owner.

## Actual baseline and human-selected scope

`test-cohort.context` requires the exact `phaseId`, `baselineOperationId` and
`observedOperationId`; `baselinePhaseId` can name another actual producing phase. Both check
operations must be retained conditional SGOS executions under the pinned configuration, matching
repository selection, command, executable/environment and configuration-file inventory. Counts
alone, incomplete occurrences, ambiguous names and nonportable paths cannot identify a cohort.

Each repository/command has its own selection, even when files and test names are identical.
Case identities bind the reported file, suite, name and framework. They deliberately describe
report occurrences, not independently inventoried source-level test identities. A failed selected
case is still in the selected scope; its execution outcome requires its own repair/risk owner.

The context supplies `expectedContext`, actual configured authority and original decision history.
History contains at most 32 summaries and immutable original references, with explicit total/truncation
fields; it does not repeat full baseline inventories. The whole human context is limited to 2 MiB.
`test-cohort.confirm` requires an explicit operation ID, that exact context and a human reason.
A reduction needs an expiry within 90 days. Only an authenticated phase approver can confirm or
revoke it. Accepted receipts append to `namespaceTestCohorts`; a lost acknowledgement replays
the original record instead of recording a second decision. JSON flags cannot provide authority.

Publication uses fresh retained checks. It verifies the selected cases against the actual run,
retains `test-cohort/v1`, and rechecks permission before publication, submission, approval and
their final commits. Expiry/revocation requires full baseline restoration or an exact human renewal;
renewal can target the original Code phase while Release is active. No receiving run is invented.
The combined profile `test-cohort/v2` can carry a separately accepted actual environment failure.

## Code failures and recovery agreements

`test-risk/v2` admits Code environment failures only after replaying actual SGOS outputs and the
cause classifier. Assertion, compilation, unknown, timeout, source-integrity and missing coverage
failures remain repair work. The Code report uses outer profile v32 and an explicit `evidenceVersion`
for the underlying v1–v31 source/history/output/verification contract. Individual failed witnesses
remain failed. Its separate execution exception declares `testsPassed: false`; it never supplies
missing source/test bindings, assurance, assertions or visual acceptance.

A mixed test/visual contract still needs its exact independently retained human visual witness.
Only genuinely covered test results can consume the separate environment exception. Missing images
and inspection decisions cannot disappear behind an aggregate failure.

With an enabled recovery agreement, `test-risk.confirm-recovery` requires an explicit operation ID
and the exact `expectedRecovery` returned by `test-risk.context`. The pinned policy must enable
`validation-unavailable`, its configured authority must approve, and its maximum lifetime applies.
The v3 decision/report binds the actual confirmed agreement and exact failed execution. Ordinary
`decision.test-risk` cannot silently bypass that agreement. A full-command agreement without this
category keeps requiring real repair and successful execution.

## Later phases, final evaluation and takeover

Namespace evidence context/evaluation v4 reconstructs current execution permissions from their
authenticated original receipts. It retains separate scope/risk rows and exact original-owner
actions. Expired Code permissions remain visible during downstream phases; they cannot become
generic duplicate obligation decisions. A closing vote retains terminal evidence v2 and rechecks
the current observations before its conditional commit. Historical publications and approvals stay
immutable, and an accepted original vote can be replayed without a checkout or new clock.

Real missing content, permission errors and storage deadlines propagate with their original
identity/details. Only the original policy-domain refusal becomes an uncovered permission row;
I/O errors cannot masquerade as expiry or absence. Source and uploaded inputs remain behind their
existing workspace/device ports. None of these operations executes a model or changes native Git
storage authority.

## Boundary and remaining work

Kernel rules own cohort identity/coverage and execution exception values. SDK operations coordinate
exact contexts and original human decisions; SDA retains content and conditional receipts; SGOS
owns every actual process and test report. Hosts render actions and provide authenticated access.
The installed offline SDK exports the new operations and strict NodeNext value contracts through
the existing `testing/recovery` entry point.

This observed-suite baseline is not a pre-feature inventory or a waiver for known code failures.
Independently inventoried selective recovery, known-failure decisions, environment-sensitive
cross-execution reuse, live application review/comparison and the other execution/policy owners in
the completion ledger remain separate. Required capabilities cannot become successful flags.

## Mac qualification

All 286 distinct targeted Mac tests pass: 129 runtime/value/compatibility cases, 114 architecture
guards, nine operation/native-entry inventory cases and the original 34-check package qualifier.
There are no failures, cancellations or skips in that qualified set. Real journeys cover filesystem,
SQLite and application storage, two repositories, mixed visual acceptance, expired/revoked scopes,
original-owner renewal during Release, lost acknowledgements and original I/O errors. The offline
consumer publishes a genuine failed Code execution with a separate cohort/risk, independently
approves it, evaluates final evidence and replays its receipt without a checkout or executable PATH.
NodeNext contracts reject invented flags and missing required inputs.

The original package test is unchanged and ran alone in 93 seconds under its original 120-second
parent and 60-second child limits. Source validation passes 4,388 checks. VS Code typechecking,
the 2,011-site Git audit and all 13 original bundle ceilings pass unchanged; the gateway remains
852/852 modules at 6,939,111 bytes. Windows CI, live providers, real Stories, installation changes
and a main merge are outside this qualification. Neither Phase 5 nor Phase 7 is marked complete.
