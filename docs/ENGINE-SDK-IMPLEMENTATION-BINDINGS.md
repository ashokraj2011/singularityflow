# Shared implementation bindings and review choices

Implementation bindings connect a planned clause with its changed source regions and the
author's explanation. Public symbols are an explicitly heuristic aid to the reviewer. Shared
value rules now assemble these bindings and interpret reviewer choices; filesystem, Git and
lifecycle authority remain outside those rules.

## Boundary

`implementationBindingPolicies(paths, digests)` in `kernel/code-delivery-evidence.mjs` accepts
only the existing frozen path-syntax and SHA-256 UTF-8 primitives. It returns a generator over
two explicit requests: `implementation-diff-preview` asks for exact zero-context regions in the
selected paths; `implementation-source` asks for one source body under the existing 2 MiB limit.
The generator memoizes source replies for that invocation. Original request errors propagate;
the rules never discover a checkout, execute a process or turn an error into successful evidence.

The native adapter still uses the existing Git diff projection and its original best-effort
source reads, UTF-8 decoding, NUL handling and byte limit. It owns no clause, explanation, symbol
or review-selection policy. The existing native `bindingsDigest` export and native receipt replay
use the shared digest rule. No native record version, serialized binding hash or error vocabulary
changes. Legacy diagnostic wording is retained for compatibility; command rendering remains in
the host.

`kernel/code-documentation.mjs` owns public declaration observations and changed-declaration
selection. `kernel/polyglot-lexical.mjs` owns the original closed masking/import/symbol grammar.
Path classification uses explicit syntax primitives; local-import resolution requires path-syntax
v2. Compatibility exports retain their original names. The native persisted verification scanner
fingerprint includes these extracted owners, so later rule changes invalidate old cached facts.
Both new kernels are required staged CLI files and contribute to the native build identity.

## SDK use

The `specifications` entry exposes the pure factories, source observations and `reviewBindings`.
The optional `specifications/node` entry supplies explicit Node path/hash bindings. It opens no
project, cache, filesystem, Git executable or model connection. The installed consumer can replay
captured original region/source facts with infrastructure imports denied and an empty PATH.

The input obligation list is candidate data, not an approved plan. The host admitting application
publication must separately authenticate the plan, retained source bytes, diff provenance, test
execution, generation and authority. Supplying a value reply does not authorize a publication.
Review selection returns the existing batch digest and accepted/exception choices; it does not
authenticate the reviewer, commit a decision or approve a phase. The native approval operation
keeps its original identity, lifecycle, authorization and freshness checks around that rule.

No modified file is described as wholly changed merely because its precise diff is unavailable.
The native compatibility result preserves that unavailability. A complete portable code-delivery
owner still needs actual baseline/current regions and accepted source/claim proofs; this helper
does not waive them or accept a caller-provided readiness result.

## Compatibility evidence and remaining work

The independent oracle was captured at `ce0f19d2e` before extraction, with SHA-256 identities of
the three original owners. Its 27 genuine Git/file cases cover tracked, staged and untracked
changes, renames, deletions, separate hunks, empty/binary/invalid UTF-8/oversized bodies, JSX,
CRLF, missing/short/long explanations, duplicate paths, ordering and multiple source languages.
It also captures 15 declaration cases, 11 path cases, 16 lexical cases, four local-import cases
and nine native reviewer-choice outcomes. The oracle is not regenerated by the extracted rules.

Complete namespace application-publication policy and its source hunk, claim, constitution,
artifact-set and execution owners remain required. Complete cross-agent application Story
execution, migration of existing authority and final distribution/performance qualification are
still open. This advances the remaining Phase 5 and 7 work; Phases 5, 7, 8 and 9 remain incomplete.

## Mac qualification

Qualification passed 355 distinct affected cases without failures, cancellations or skips:
187 core/value, architecture and namespace-reader cases; 137 native delivery, approval, cache and
polyglot cases; and 31 installed offline SDK-package cases. Initial repeated value checks are not
added again to that total. The native approval group compares actual CLI/SDK receipts, one-time
selection use, partial thresholds, duplicate reviewers, authenticated authority and failures after
an accepted commit. No approval identity or lifecycle requirement was replaced by a value reply.

The installed consumer replays the original Git/file oracle with infrastructure imports denied
and an empty PATH. NodeNext checks accept the explicit request/reply protocol and reject checkout,
readiness and lifecycle-approval inputs. VS Code types and all 13 unchanged runtime bundle budgets
passed; gateway/extension remain 852/152 modules, with Help/support/prewarm at 135/111/23. The SDK
keeps 60 registered operations across 211 owned modules and 2,180,240 JavaScript bytes. No timeout
or module ceiling was increased. No Windows, hosted CI, live model, product install, real Story
mutation, merge, push or authority cutover was performed.
Source validation also passed 3,995 checks across 191 skills with the existing Git ownership audit.
