# Plan and evidence correction rule boundary

The kernel now owns plan row normalization, operation application, exact row/map binding, authority
selection and evidence-contract projection. Native adapters supply presence-counted records and
keep committed Git file verification. Existing correction IDs, record hashes, direct-terminal
review assurances, native schema APIs and refusal meanings remain unchanged.

Structural declarations belong to the kernel. A foundation reader interprets those declarations
without host I/O; native compatibility schemas expose the same declarations through the existing
Zod API. Upstream issue values use that same structural reader. Validation cannot be replaced by
a caller-supplied successful outcome.

The optional SDK exposes the pure `planCorrectionPolicies(paths, digests)` factory through
`@singularity-flow/engine-sdk/plans`. Paths and hashing are explicit primitive capabilities.
`evidenceCorrectionProjection` constructs an exact before/after value; `applyPlanCorrections` and
`applyPlanEvidenceAmendments` accept an explicitly admitted record inventory. These value functions
authenticate no human, consume no review authorization and perform no persistence. They cannot
approve a phase or waive required test execution.

Namespace recording of a correction remains a separate owner. It must bind the exact approved
plan and human review through accepted transactions. It must not label a namespace confirmation
as the native v1 `live-terminal-exact-plan-review` ceremony. No installed authority or stored record
was migrated by this extraction.
