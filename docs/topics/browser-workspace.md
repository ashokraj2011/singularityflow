SFlow can run an independent local service and open its browser workspace. VS Code is a client of
the service; opening it does not reopen folders or reload the editor. The Engine SDK migration is
separate and is not required or included.

## Open and reconnect

From the intended checkout, run `singularity-flow ui open`. Or choose **Singularity Flow: Open
SFlow in browser** in VS Code's Command Palette; it is also available as a pinned shortcut. The
CLI uses the runtime that launched that installed SFlow build. VS Code launches its selected SFlow
CLI/runtime pair, never code from the Story's repository.

`--no-open --json` returns the one-use browser URL without launching a browser. Its fragment ticket
expires after one minute, is removed from browser history on exchange, and is not a native control
credential. Do not share this link. Reopen through the CLI or editor after session expiry.

The native commands are:

```text
singularity-flow ui open [--no-open] [--idle-minutes 1..60] [--resume-request INVOCATION-ID] [--json]
singularity-flow ui status [--json]
singularity-flow ui stop [--drain] [--json]
singularity-flow ui serve [--idle-minutes 1..60] [--json]
```

The Copilot route `/sf-ui` inspects status and shows the native opening routes. A model turn never
receives a browser bootstrap grant or native control credential. `serve` is a foreground diagnostic
host, not a workflow phase. `stop` refuses while operations are active; `--drain` stops accepting new
work and lets admitted operations finish. There is no PID-based force-kill command.

## Current browser scope

Spec Studio supports creating a business or technical draft, editing its wording and title, explicit
save (also Command/Ctrl+S), a safe preview, quality checks, saved versions and supporting sources.
IDs are generated by the existing specification owner. Saves retain its sequence and operation ID;
a stale edit is refused while unsaved text stays in the tab. Compare the newer writing or save
your version as a separate draft. A lost save reply can be checked against the original snapshot
without repeating the save. Browser upload is limited to 5 MiB per
file. Documents and images use the existing local source store; only descriptors may later travel
with a shared specification. A missing original requests the matching file on that computer.

Stories can be searched, sorted by their column headings and opened into this tab's context. The
default is creation date descending. Catalogs, Decisions and Run & Test currently expose canonical
read results. Management edits, imports, activation, application/test execution, person-only review,
publication and approvals continue through their existing native surfaces during this rollout.
These read pages do not claim completed management-menu migration.

When a matching VS Code window is connected, **Continue with Copilot** prepares the existing
`/sf-spec-author` request in that window. The person chooses Send. Delivery is not model execution,
completion, acceptance or approval. A disconnected or different-checkout bridge is refused.

## Isolation and lifecycle

Each tab has its own context handle, even though browser cookies are shared. Browser requests never
carry arbitrary checkout paths, shell commands or CLI argument arrays. Canonical operations run
with the explicit context root; this service does not change a process-global working directory.
Eligible reads reuse SFlow's private read workers. Other owners run through an isolated canonical
CLI child, with models disabled and original errors retained.

The service binds only to `127.0.0.1` on an assigned port. It has private native discovery and
credentials beside the workspace registry, under `browser/`. This is transport metadata, not another
Story/state store. `SINGULARITY_FLOW_UI_ROOT` redirects it for isolated qualification. No source,
worktree or original document is copied into the service's metadata directory as permanent state.

The native client's environment is scoped to its own grants and workers; another window does not
inherit its credentials or identity. Raw environment values stay in memory, outside browser
responses and transport receipts. Changed credential scopes cannot reuse an old write receipt.
Startup and the service lifetime use the existing fenced lease owner, including its PID-start check.
Native control uses authenticated request/response proofs and encrypted inputs. A process reusing
an old loopback port receives neither the native credential nor the client's environment. The
editor reads the exact private discovery path returned by its CLI, including custom state locations;
opening a second browser tab keeps the first tab's matching editor connection.

Routine JSON control requests are limited to 256 KiB. Wording and local file bytes use separate
bounded content routes, with a 5 MiB upload limit. Activity lists return summaries instead of
retransmitting previous document bodies. Service failures retain the original code and deadline
and offer local-service recovery, without sending a person through unrelated Story diagnostics.

The default idle timeout is 10 minutes, configurable through `--idle-minutes` on startup or
`SINGULARITY_FLOW_UI_IDLE_MINUTES`, from 1 to 60. A compatible existing instance retains its current
timeout. Active work prevents idle shutdown. Closing the editor does not kill the service.

Requests have stable invocation IDs, separate from HTTP attempt IDs. The browser inspects the
original receipt after a lost reply. A service restart marks unfinished transport records unknown;
it does not repeat mutations or infer whether they succeeded. `ui status --json` lists unresolved
records and recent writes, including completed writes whose browser reply may have been lost;
`ui open --resume-request ID` reconnects their original client/context for inspection. The canonical
draft/history/result remains authoritative. A token, checkbox or browser session never substitutes
for the existing human signer.

## Platform and update boundaries

The first qualification scope is local macOS. Native Windows ACL and process-lifetime qualification,
remote port forwarding, embedded views and complete menu migration are unreleased. The Windows
launcher refuses explicitly rather than storing credentials under unverified permissions.

A mismatched active service is refused with `UI_BUILD_MISMATCH`. Drain it using its existing build,
then launch the new build. This preview does not add automatic installer artifact cleanup or modify
workspaces/recovery. A development checkout is identified as such; equal package versions alone do
not establish build alignment.
