# Namespace specification publication

Specification and planning phases now retain their derived clause index and planned claim map
through the same registered `phase.publish`, `phase.submit` and `phase.approve` operations as other
namespace-backed documents. This advances migration Phases 5 and 7; Phases 5, 7, 8 and 9 remain open.

The optional namespace host selects this policy from the pinned responsibilities and claim topology.
Phase names do not confer authority. Installed Git hosts retain their existing writers and records.

## Records and proof

The new publication manifest is schema 3 with the `sflow-specification-publication/v1` profile.
Publication schemas 1 and 2 keep their exact shapes and meanings. Schema 3 requires a versioned
specification-evidence binding and permits a nullable check binding; actual checks still need their
original execution proof. The existing generation publication reference remains version 1.

Specification evidence binds the original artifact bytes, draft revision, author, agent,
configuration, generation, operation, timestamp and lifecycle basis. It retains the native version-1
clause index and version-2 planned claim values as content-addressed evidence. Their source path is a
logical Story artifact key, never a laptop path or an invented source commit.

The read-only proof owner replays these values from the original artifact and pinned policy. It
verifies every contributing earlier definition against its actual publication, submission and human
approval threshold. Only active, preceding, pinned clause producers contribute requirements. A
later definition cannot replace an already approved clause. The publication receipt must conditionally
accept the same lifecycle basis and retain every derived evidence reference.

The content writer has a separate module and cannot mutate lifecycle authority. Submission and
approval satisfy specification/plan requirements only through the proof reader's private verified
objects. A caller-supplied readiness flag, an edited index or a new content digest grants no authority.
Changing an already checked object invalidates its private proof. Future binding, manifest and
derived-record versions stay unsupported; damaged records are corrupt, and actual storage-read
errors retain their original identity and details.

## Shared rules

Native and namespace publication share clause-producer selection, required stable anchors, claim
allocation and exemption checks, primary test slots, runner profiles and assurance ceilings. Native
file reads, command inference, launcher checks, messages and records retain their existing owners.
The original public verification-contract factory retains its method set.

Namespace planning inspects the pinned command declarations without searching a repository or
launching tests. Missing test configuration is retained as pending. An explicitly insufficient
assurance ceiling is refused before code authoring. A declared runner or present test file is never
passing execution evidence; launcher availability remains explicitly unobserved.

Proof reuse lasts for one read traversal and is held behind opaque, private cache tokens. It cannot
be seeded by operation data or reused as a long-lived authority cache. Conditional lifecycle
acceptance and the original human approval checks remain required.

## Compatibility and remaining scope

This integration supports ordinary specification and plan duties with the required surrounding
policy owners available. Required clarification, quality analysis, constitution, qualified skill
hosting, artifact sets, application-code delivery, execution and other production policies continue
to require their own verified owners. This does not qualify complete application publication or an
entire headless application Story.

Existing projects are not migrated. There is no installed Git cutover, installation, merge, push,
live provider execution or Windows qualification in this slice. Migration and old-writer fencing
remain Phase 8 work; final cleanup, distribution and performance qualification remain Phase 9 work.

## Mac qualification

Qualification passed 351 distinct affected cases: 248 native/namespace regression tests, 74
architecture checks and 29 installed-package cases. The final policy rerun also passed all 59
specification and publication cases. These sets contain no failures, cancellations or skips.

The installed-package case creates, authors, publishes, submits and independently approves real
specification and planning phases, then reopens their original receipts in another empty-PATH
process. No source checkout, CLI or Git executor is available to that consumer. Native adapter
profiles and command specificity match an independent pre-extraction capture. Retried timestamps,
actual check execution, BOM-bearing source bytes, future schemas, corrupted records, object mutation
and real permission/timeout failures are covered.

Source validation passed 3,965 checks across 191 skills. VS Code typechecking, the existing Git
ownership audit and all 13 unchanged bundle ceilings passed. The gateway remains 852/852 modules
and the extension 152 modules. The SDK keeps 57 operations across 194 owned modules and 1,924,223
JavaScript bytes. These are compatibility and packaging results, not Windows or latency claims.
