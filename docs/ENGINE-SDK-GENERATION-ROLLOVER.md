# Reviewed generation rollover

`engine.run('phase.rollover', {workId?, phaseId?, confirm?})` and
`engine.rolloverPhase(inputs)` preview a native code-generation successor. Supplying the exact
current confirmation opens its local generation receipt through the installed draft transaction.
The CLI's `phase rollover` uses the same registered coordinator.

## Boundary and confirmation

The kernel captures the Story, selected phase, published generation and next allocation before
awaiting native inspection. Existing generation high-watermarks still prevent identity reuse.
The native Git port inspects the authentic prior publication and current result and application
changes through the existing recovery planner. It retains the native submitted-generation,
unavailable-authority, manual-recovery and invalid-route refusals.

The SDK receives a `sflow-generation-rollover-plan/v1` with the captured identities and exact
current digests. It receives no laptop path, model prompt or rendered command. The confirmation
must equal the application change-set digest when one exists, otherwise the current result digest.
Omitting confirmation or supplying an empty string yields a preview. A stale confirmation refuses before
the writer. Changed files require a new preview and reviewed confirmation.

The port's native begin transaction still checks the source boundary, protected paths, current
bytes, installed phase authority, Story lock and expected revision. Its original preimages,
journal, rollback and receipt verification remain unchanged. The installed lifecycle generation
and prior publication remain preserved; the new receipt belongs to the monotonic successor.
Neither preview nor begin commits, pushes, runs tests, publishes, approves or advances a Story.

Confirming current bytes authorizes this local authoring boundary. It does not record human
evidence, phase approval or permission to bypass an edit guard. The plan explicitly disclaims
mutation authority, approval and final publication binding checks. The receipt separately reports
whether the local successor was opened and its draft saved.

## Native compatibility and recovery

The native Git port loads the accepted Story once. Existing recovery inspection, route validation
and private preview remain in the compatibility adapter; Shell/Copilot/model-free rendering stays
outside the kernel and public SDK. The CLI retains its original preview, confirmation text,
creation JSON and filtered refusal envelope. The pure stale-confirmation error has semantic plan
details; the CLI restores its private preview before its existing refusal presenter runs.

A submitted generation still requires an authorized rejection before a successor can be opened.
Unavailable prior publication or change-set inspection does not become consent or a waiver.
Native failures retain code, identity, cause and recovery. Optional `enginePhaseRollover`
diagnostics identify completed and pending stages and possible local effects. They cannot mask
a frozen error, assert rollback or automatically retry an unknown outcome. After interrupted or
lost-response begin, inspect the native receipt/recovery state before another operation; a repeat
rollover is not a new idempotency or retry protocol.

The existing Story branch, state proof/projection and `sflow/config` authorities are unchanged.
Native recovery planning and generation storage remain explicit compatibility dependencies.
Preparation, remaining queries, portable asset inventory and the alternate-backend/headless/
migration phases retain their scope in the [migration plan](ENGINE-SDK-MIGRATION.md).
