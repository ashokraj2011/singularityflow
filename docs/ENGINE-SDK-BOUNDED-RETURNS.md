# Bounded reviewer and upstream returns

This delivery on `codex/engine-sdk-foundation` connects configured repair budgets to actual
namespace reviewer returns and upstream-owner returns. It preserves the native Git transition,
records, errors and command presentation. It does not complete Phase 5 or 7.

## Owners and records

The kernel owns budget selection, consumption, reset values and structured exhaustion actions.
The native adapter still supplies its original shell guidance and generation-reset behavior.
Eleven cases captured before extraction compare native results, errors and mutated values.

The SDK authenticates the original publication, submission and human decision before consuming
an attempt. SDA conditionally accepts the return, counter and history together. Later Code
generations still need their actual source observations, fresh SGOS test execution and configured
human approval. A counter is not test evidence, risk acceptance or permission to change scope.

| Record | Meaning |
| --- | --- |
| Native repair-budget state v1 | Original fields and native reset semantics |
| Namespace human decision v1 | Original returns without the new budget provenance |
| Namespace human decision v2 | Reviewer return bound to its original counter and reset approval |
| Namespace upstream return v1 | Original producer and owner provenance |
| Namespace upstream return v2 | Same producer provenance plus the shared repair-budget transition |
| Namespace repair-budget source v1 | Pinned policy, actual approved reset generation and prior return |

Opening or copying a reset generation does not reset a namespace counter. The reader verifies
the original reset publication, submission and active approval threshold. An explicitly allowed
self-approval stays allowed and disclosed. Returning to the reset phase preserves the consumed
counter until its actual replacement approval exists. Historical replay preserves the original
time, decision and counter; a lost acknowledgement does not create another attempt.

The current counter and complete history must match their last accepted return. Removing history,
clearing counters or changing their receipt inventory is refused. Lifecycle byte and structure
limits apply during decoding and acceptance; the reader adds no unrelated history-count ceiling.
Exhaustion returns structured operations and missing inputs for the actual submitted reviewer or
upstream-owner context. It cannot manufacture a submission packet or human disposition.

Configured decision-loop rounds remain their separately owned native contract. This delivery
does not implement automatic test-recovery agreements, targeted repair, test narrowing or a model
repair loop. Those owners remain in the completion ledger.

## Reads and storage

Original accepted lifecycle, source-baseline, retained-source and check proofs may be reused only
inside one awaited SDK invocation. Current index, source, identity, head and authority observations
stay fresh. Mutations invalidate the read session even if their acknowledgement is lost. Missing
or pending evidence is not cached. Cache limits remain 256 entries and 8 MiB; completed original
proofs may displace lower-priority completed observations within those limits.

Inspection capability identity includes both the captured method and its receiver. Only owned
captures normalize a bound method to that original capability. Copied or decorated observers and
different receivers cannot borrow another reader's proof. Original permission and timeout errors
propagate; cached values are private copies with the source reader's authenticity checks intact.

A private SDA capability batches up to eight explicit record/receipt observations from one real
journal snapshot. Public v1 stores and their sequential fallback stay unchanged. Filesystem journal
reads still reopen and check the retained entries; this work does not weaken integrity scans.
There is no cross-request cache or new public storage writer.

## Mac journeys

The complete four-Code-generation reviewer-return journey passed on filesystem, SQLite and
application storage. It includes exhaustion, a real reset specification and plan, replacement
approvals, four actual test processes, lost-acknowledgement recovery and checkout-free replay.
Observed whole-journey times were 326.1, 74.7 and 87.8 seconds respectively. The filesystem
integrity scans remain a material cost.

The separate upstream-owner journeys passed in 62.3, 23.1 and 25.4 seconds respectively. They
consume the same counter, preserve the actual producer and require a genuine owner disposition
when the next return is exhausted. Neither journey invents a passing check or a human vote.

The new entire-Story test has a ten-minute limit. Its earlier 180-second development limit proved
too short for the filesystem journey; those cancelled runs are not qualification. The original
installed SDK qualifier remains unchanged, with its 120-second parent and 60-second child limits.
The unchanged installed qualifier passed all 34 checks in 47.5 seconds when run alone. The new
offline installed return/replay case passed in 27.9 seconds with an empty `PATH`, after removing
the source checkout. Both preserve original receipts across separate processes.

Final qualification passes 612 distinct affected Mac checks, including 79 native compatibility
checks and 95 architecture checks. Final qualifying runs have no failed, skipped or cancelled
tests. Source validation passes 4,240 checks; VS Code typechecking, the unchanged Git ownership
audit (2,011 sites) and all 13 original bundle ceilings pass. The gateway stays at 852/852
modules. The original package file, its deadlines, bundle policy and Git audit baseline are
unchanged. The earlier architecture failure was corrected with exact memo-only import guards;
Story construction and mutation remain forbidden in those proof readers.

Tests ran on this Mac only. No main merge, Windows CI, live model, installed authority change or
production Story mutation is part of this delivery. See the
[remaining Phase 5/7 owners](ENGINE-SDK-PHASE-5-7-CLOSURE.md) before treating either phase as complete.
