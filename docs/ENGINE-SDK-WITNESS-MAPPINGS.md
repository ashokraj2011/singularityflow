# Exact test reviews and exception renewal

The namespace host now owns published test-mapping review and original-phase exception renewal.
The registry exposes `test-witness.context`; `phase.approve` can consume its exact digest through
`witnessReviewContext` and the existing `witnessMappings` answers. Omitting that context keeps the
original approval profile and behavior. The native Git adapter refuses a namespace context rather
than silently dropping it. Its existing native test-review inputs and outputs remain unchanged.

## Evidence and authority

Proposals come from the accepted Code publication, actual retained test executions, independently
approved specification/plan, criterion text, verification contract and exact test declaration.
Approved repository roots qualify paths before calculating mapping digests. Identical relative
filenames in two repositories remain distinct proposals. The context is read-only and establishes
neither test acceptance nor human approval.

One pure human-witness owner evaluates the five adequacy facets. Its native compatibility wrapper
retains the original optional clock and UTF-8 behavior. The extraction reproduces 67 independently
captured native outcomes from `3c0d359d5`, including original errors. Default batch satisfaction,
explicit exceptions/exclusions and carry-forward by exact digest retain their native meanings.
An exception names inadequate facets, a reason and a future expiry. It never waives failed execution.

An approval records actual human answers and recomputed decisions in separate vote profiles:

| Vote version | Meaning |
| --- | --- |
| 6 | Exact mapping review |
| 7 | Mapping review and configured route |
| 8 | Mapping review and evaluated closing vote |
| 9 | Mapping review, configured route and evaluated closing vote |

Earlier versions 1–5 retain their bytes and meanings. Readers verify the original submitted packet,
configuration, actor, quorum, proposals, answers and conditional receipt. Another reviewer carries
an identical still-current decision instead of accidentally replacing an exception with batch
satisfaction. Changed retry answers cannot rewrite the original human vote. Expiry is checked again
before the conditional commit.

## Renewal and continuation

`decision.witness-exception` verifies an actual approved exception on the named phase's current
generation and its original human approval group. The Story must remain in progress. It appends
`namespaceWitnessExceptionRenewals`; it never rewrites the approval, execution or published document.
A later active phase can renew the original phase's exception without returning or recreating it.
Expired exceptions appear once in Decisions with the exact original phase and mapping digest.

The original accepted decision can be acknowledged from shared storage with the old checkout gone,
no execution owner and no clock allocation. Its separate namespace outcome reports `retained` and
`committed: false`. A lost acknowledgement preserves the original timeout and reconciles one record.
Unrelated identities, missing/unapproved mappings, malformed answers, stale contexts and failed
content reads retain explicit refusals or the original I/O error.

Evidence context/evaluation v3 admits only authenticated mapping decisions and renewals. Its input
digest includes those decisions and actual renewal receipts. Original native and namespace v1/v2
evaluations remain unchanged. An expired upstream exception prevents final closure; original-owner
renewal can resolve it in the active phase. A prepared closing vote is verified as a proposal against
its original basis, never mistaken for an already accepted receipt. Final commit checks expiry again.
