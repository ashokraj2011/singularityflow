# Fix a workflow

<!-- sflow-copilot-pause -->
Before any boundary lookup or SFlow action, run `singularity-flow pause status --json` and follow its `data.agentInstruction`. If `data.paused`, answer as native Copilot, only offer `/sf-pause off` and never resume implicitly. This skill is already loaded; never call the skill tool for it. Unless paused, continue below in this turn.

<!-- sflow-output-contract: conversational-guidance -->
**Output contract:** Resolve ordinary language through durable Home and Next projections; reads may run immediately, while every mutation requires an explicit governed choice. Summarize artifacts with verified Markdown-preview links; never paste document bodies, code or diffs into Copilot. For code, list touched paths and observed added/deleted/created line counts; unavailable stays unavailable. Use existing evidence, not extra calls solely for display. Summaries, links and opened previews are not human review or approval. Never show a person a hash, digest or commit SHA: name the step, its generation, its files. Say what happens next in one plain line ("Next: <what happens>"), never as a list of commands; run returned routes exactly, never invent one. When SFlow's note says this turn goes on, do it in this same turn. Where a person decides, say what, why and where (this question, the page or the card). Every turn that no SFlow note carries on ends with "/sf-next carries it on" (or press Continue). Where the steps say ask_user, use your host's question tool: ask_user in the Copilot CLI, vscode_askQuestions in VS Code; it is unavailable only when neither exists.
<!-- sflow-execution-boundary -->
**Boundary:** no Story required; cwd=opened Git root or verified `repositoryPath` from `singularity-flow workspace current --json`; refuse if neither resolves; never search `$HOME`/parents. Use exact CLI-returned paths. `repositoryPath` is command cwd, not a prefix for absolute file paths. Never rebase paths or strip `.git/worktrees`. Issued private/external files are exact exceptions to repository confinement, not wider read/write permission; writes still need authorization. Resolve relative paths only against their declared base. On failure, preserve the path and error; never search or recreate it.


Nothing changes until the proposal is reviewed and activated; you never approve or activate.

1. Run `singularity-flow workflow validate <WORKFLOW> --for-start --json` (exit 1 with findings is this skill's input, not a refusal) (no `<WORKFLOW>` checks all). If `valid`, say so in two lines from `roles` (which step defines the clauses, plans each code step, carries the tags, reviews). With `simplify` it is correct but heavy: name `simplify.found` and offer `simplify.nextAction` (a simpler copy, each change the person's; the original never changes). Then step 6.
2. For each `problem` in `workflows[].findings` and `repository.findings`: what is wrong (`title`, `location`), why it stops a Story (`blocksStart`: Story start refuses it; else `stopsAt` names the step and when), and `fix.text`. Warnings get one line each; skip notes.
3. With `fixDraft.fixCommand`, run it: it writes every change it drafts to `fixDraft.changeSetPath`, asking nothing; ask only its `questions`, one at a time, with `ask_user`, and write each answer into that draft (step 4). Otherwise ask with `ask_user` only what is the person's: which agent drafts a step, approval groups, whether a route may omit a responsibility and why. Never ask for template content: its fix is the placeholders shown (`TODO`, `{{work.id}}` anchors). Offer choices from the findings and the repository; never invent people, groups or reasons. Never fix by removing a review, lowering approvals, or declaring omits without the person's reason and group.
4. Keep every fix in one change set `{ "schema": <fixDraft.schema>, "changes": [...] }` at `fixDraft.changeSetPath`, edited with a file-edit tool. Use a finding's `fix.changes` as given; otherwise Studio ops: `phase.agent` {phase, agent}, `phase.update` {id, workflow, approval: {groups, minimum, rejectTo}}, `workflow.update` {id, plannedClaims}, `template.update` {path: the finding's `subject.template`, content: the whole template, its wording kept, plus the fix's placeholders}. Run `singularity-flow workflow check <WORKFLOW> --change-set <fixDraft.changeSetPath> --json`: the targeted problems must be gone and none added. Repair the draft at most twice, then show what remains.
5. Run `singularity-flow workflow studio apply --change-set <fixDraft.changeSetPath> --dry-run --json` and show its `summary` and `files`; for a template, say in one line that it adds placeholders each Story's author fills. Only on the person's confirmation, run `singularity-flow workflow studio apply --change-set <fixDraft.changeSetPath> --propose --json` and report the proposal branch. The reviewer approves in Workflow Studio → Changes, or runs `singularity-flow configuration approve <BRANCH>` in their own terminal. Then step 6.
6. Assess what each step's agent is told: `singularity-flow workflow assess <WORKFLOW> --json`. Show `verdict.text`, the size, and per step each finding's `title`, `location`, `quote` and `suggestion.text` with its `saving`. Then judge what rules cannot see: read each step's parts (`singularity-flow workflow assess <WORKFLOW> --read <STEP> --part <N> --json`; `found` is SFlow's) and write contradictions, unclear wording and leaner rewrites, each quote exact, to `next.findingsPath` as `{ "findings": [{ step, file, line, quote, kind, why, rewrite? }] }`. Verify: `singularity-flow workflow assess <WORKFLOW> --verify <next.findingsPath> --json`; repair each `refused` as its `repair` says and verify again in this turn. Show `accepted` as Copilot's.
7. Apply with `next.apply`: each checked suggestion is a proposal with its `effect`. Ask with `ask_user`: accept all SFlow's own (`singularity-flow workflow build decide --build <ID> --accept --all --json`) or each (`--proposal <P> --accept` or `--decline --reason <TEXT>`). Propose accepted Copilot findings' `suggestion.moves` through the build's `proposalPath` (`singularity-flow workflow build propose --build <ID> --proposal <proposalPath> --by copilot --json`). Run `singularity-flow workflow build verify --build <ID> --json` and show `assessment` and `remaining`; on the person's word, `singularity-flow workflow build finish --build <ID> --propose --json`.
