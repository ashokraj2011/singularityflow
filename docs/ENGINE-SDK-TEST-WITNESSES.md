# Exact test witnesses in the SDK preview

`phase.test-witnesses.inspect` joins the exact test declarations in accepted source archives to
their own occurrences in the exact retained phase-check run. It uses the same witness rules as
native publication, review and evidence views. It is a read operation, not publication admission
or application acceptance. Existing `phase.delivery.inspect` result versions stay unchanged.

The public entry is `engine.run('phase.test-witnesses.inspect', {phaseId, maximumEntries})`.
The main namespace Engine and `hosts/namespace-test-witnesses` compose the same registered port.
An explicit machine-local candidate, shared records/content, source units and read permission
are required. The operation does not start a model, test runner or application, write a draft,
publish, submit, approve, accept a risk or advance the Story.

## Evidence and ownership

The kernel owns declaration identity, per-test occurrence matching, profile assurance, runner
disambiguation, witness discovery and bounded result validation. Legacy imports remain aliases
or native observation adapters. Actual native command resolution and language-specific readers
stay in their host; shared rules do not read files, Git, environment variables or a provider.

The namespace reader reopens the original independently approved specification and plan,
accepted source archives, check intent and results, raw reports and conditional receipts.
Results are reconstructed from those bytes; stored counts and a successful exit code cannot
substitute for a test's identity. A Node exact witness needs its own file, line, name and suite.
Other passing tests, another repository's identical relative filename, duplicates, skipped tests
and incomplete or failed runs cannot provide its pass.

The reader compares the run's source inventory with the actual archived declaration source
before joining them. A newer archive cannot borrow an older run. When the current checkout
drifts after a matching archive/run, the historical result stays visible alongside false source
and check match flags, with explicit source-retention and check-run actions.

Repository-root projections retain their approved identities. Shared namespaces additionally
need accepted original AC-line provenance; carried tags cannot become the current Story's
witnesses. Missing original bytes, declaration adapters and provenance have named owners.
Permission, missing-content, timeout, cancellation and corruption errors retain their causes.
Fresh source, evidence-index, draft and access checks still occur before a result returns.

## Explicit Node reporter

Plain TAP remains readable as counts. It lacks the exact passing file identities required by
the Node witness profile. `testing/node-test-reporter` exports the existing native event reporter
as a standalone SDK entry, suitable for Node's test reporter option. A host explicitly selects
its resolved URL and root in the pinned check environment and authorizes that execution manifest.
This does not change a repository's approved argv, global Node configuration or existing checks.
The reporter itself executes no repository source and is never imported by the pure SDK.

## Result boundaries

`sflow-test-witness-inspection/v1` contains original proof references, per-repository match flags,
complete totals and bounded rows for each planned criterion/test slot/path. Each row shows its
own joined witness outcomes and assurance. Source code, raw test output, physical checkout paths
and provider prose are excluded. A display budget of zero keeps complete totals and freshness
checks. Unknown fields, authority shortcuts and inconsistent totals are refused.

Rows describe test evidence only. The original global verification contracts, their `all`/`any`
combination, supporting slots and human visual/inspection obligations are not replaced by local
test passes. The manifest explicitly says `verificationContractsCombined: false` and
`applicationAcceptanceEstablished: false`. Full publication policy, complete cross-agent
application execution, installed authority migration and distribution/performance qualification
remain required. Phases 5, 7, 8 and 9 remain open.

## Compatibility baseline

The frozen baseline at `0191309b3` captures 738 original witness/assurance outcomes, four actual
native declaration-discovery cases and 17 original rule-body fingerprints. Capture precedes
extraction; the tests do not regenerate this oracle. All eight replay checks pass, including
exact Node/Jest identities, unattached tags, count-only profiles and runner selection.

Mac qualification passes 212 distinct affected tests, with no cancelled or skipped cases. The
176-case regression group includes all three namespace backends, original error identity,
independent read permission, stale source/run separation, shared AC-line origins and two
repositories with identical test paths. Its two adapter-owner guard failures were corrected and
the complete architecture and baseline replay group passed again (89 cases).

The 36 installed-package cases run separately within their existing deadlines: core exports,
runtime and TypeScript compatibility (32), original source/plan portability (3), and exact test
witness takeover (1). The last test installs the actual archive, removes the original checkout,
reads its retained run, executes another explicitly pinned run and preserves original intent
and Story state. Source checks, VS Code types, SDK staging and all 13 existing runtime bundle
budgets pass. The gateway stays at its unchanged ceiling of 852 modules. Git/process ownership
audit reports no additional production sites. This is affected-scope Mac qualification, not a
full release or complete application Story qualification.

No Windows, hosted CI, live provider, product install, merge, push or real Story change is part
of this work.
