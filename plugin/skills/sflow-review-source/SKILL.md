Summarize artifacts with verified Markdown-preview links; never paste document bodies, code or diffs into Copilot. For code, list touched paths and observed added/deleted/created line counts; unavailable stays unavailable. Use existing evidence, not extra calls solely for display. Summaries, links and opened previews are not human review or approval. Each action: "<timing> — <label>", then its three separate Markdown bullets, in order: "- Copilot: `<copilotCommand>`", "- Shell: `<command>`", "- VS Code (model-free): `<modelFreeCommand>`". Keep returned routes exact; never apart from their label, on one line or in a table. Missing Copilot: "no verified equivalent"; missing Shell or model-free: "not available for this action". Never invent routes or make more calls for formatting. Run a check only when a returned field or command asks for it; never decide from a step's name, kind or route that it applies. A refusal saying a check does not apply to this step is not a blocker: skip it and continue. Act on a result's `act` first: its state, `do` routes and any `ask`. View each `agentOutput.read` range and `need` text file in one response at its exact issued path in `.sflow/out/`, unless this chat already read that path (same path, same bytes); other `omittedFields` are optional. A cut-off, empty, running or inaccessible host result uses `singularity-flow result last --wait --command "<its words>" --for-agent --json`, never a command replay or shell read of the host's copy. Recover read-size/range failures with returned `readRequests`/`readRanges` in your file-view tool's parameters; finish all required ranges and continue this task. Use exact `pathCorrections`; never guess paths. Real missing-file/permission errors retain their path, native error and owner recovery route; never recreate inputs or retry unchanged access. Read `taskResume` on entry: keep its operation ID, spent budgets and exact next step across chats; obtain fresh context and local paths. Before ending, honor `taskCompletion`: input reads, preparation and diagnostic tests alone do not complete authoring or review. Preserve human decisions and explicit single-step boundaries.
<!-- sflow-execution-boundary -->
**Boundary:** reuse this invocation's review entry: require `ready`/`workId`, valid `phaseAgent`; cwd=`repositoryPath`, or as is from a non-Git (chat) folder: SFlow finds the bound checkout; never refuse or wrap for it. Use returned `workItemRoot`/artifact and Git-private staging paths; never `$HOME`. Use exact CLI-returned paths. `repositoryPath` is command cwd, not a prefix for absolute file paths. Never rebase paths or strip `.git/worktrees`. Issued private/external files are exact exceptions to repository confinement, not wider read/write permission; writes still need authorization. Resolve relative paths only against their declared base. On failure, preserve the path and error; never search or recreate it.

Every step of a new Story is reviewed, code included; its submission waits for this review. Explicit `stage`/`check`/`submit`: relay once. `status`: read. Legacy `decide`: retain phase/finding/reason; hand off to `/sf-review-decide` in a new turn. Never confirm/decide as reviewer. Unknown: help, stop.

**Resume the operation:** read `progress` first. `author-report`: write the report now. `repair-report`: read the exact existing `stagingPath`, preserve its work, apply the returned repairs and check the changed packet. `retain-report`: run `progress.nextAction` now. `retained`: report the retained result and its continuation, then end. `read-error`: preserve work and report the exact blocker. A check's `reload-context`: inputs changed; follow its act (fresh context, review again). `afterRetention` is future guidance until retention succeeds. Never finish merely because reading is done, decline to retain honest correction-required findings, or relay the context command while report authoring remains. A host continuation marked `SFLOW_SOURCE_REVIEW_INCOMPLETE` belongs to this same invocation: reuse its entry and reads, then finish the outstanding write/check/retain step. A real authority, input or tool failure remains a stop. `agentOutput.view` describes the display, never the review; use the issued safe ranges, including an omitted field's `read` ranges when present.

`review-changed-inputs`: this entry is already fresh; the prior draft is preserved at `progress.previousDraftPath`. Independently re-review the current inputs and author from the current template at stagingPath; never transplant old binding or judgments or enter context again. Read pinned `clarifications`/`clarificationGuidance`; acknowledge `clarificationsReviewed` IDs and phase/generation/question. Never re-ask settled answers. Deferred answers waive nothing. Correct mistaken reviews in this generation; real gaps need successors.

1. Read `reviewGuide.readOrder`; no inventory rescans. Include explicit phase initially. `canReview: false`: relay `continuation.actions`, stop; only the author prepares/publishes successors. A missing original is restored through its returned route, never by recreating the Story. Require published `reportTemplate.binding`, `kind: specification|planning|document|code`. Unavailable/truncated sources: name their IDs and stop; route to `/sf-documents`. Inspect `visualSources` with native image/PDF tools; fill `visualSourcesReviewed` with actual method, page/region and observations. Cite them via row attestation, never invented text lines. No suitable tool: ask for help or a text export. `unreadableSources` need human `unreadable:<DOC-id>` decisions (step 5), never quotes.
2. Follow `reviewer.effectiveInstructions` when supplied, otherwise `reviewer.instructions`; no agent setup/selection. Retain as `requiredReviewerAgentId`, preserving author. `blocked-author-conflict`: relay `recovery.actions`. Compare authored-content hashes. Never edit sources, artifacts, tests, workflow, approvals or history.
3. Fill `reportTemplate` against `reportSchema`; preserve binding/metadata. `citationGuide`: source text-file lines, not JSON; exact single-line quotes. Map all scenarios/clauses, including clarified ones; real gaps need blocking findings. Attest only unreadable and inspected visual sources. Planning: singular `clauseId`, exact `expectedPaths`/`plannedTests`; test-only needs no product paths. Document: a cited row per source. Code: all four `citationGuide.checks`; each finding names its `check`, cites file:line; design blocks only with a `defect`. Replace `unreviewed` honestly. Findings: `id`, `severity`, `message`. Never mark a real gap supported merely to pass validation.
4. Use `stagingProtocol`: `kernelStage` with shell-quoted JSON, or a file-edit tool at its exact path. Native file-read; no shell writers/parsers, mkdir, pipes/chains. Run `singularity-flow review-source check <phase> --report-file <that-path> --json` standalone. Apply `repair` citation/mapping hints now, at most two changed-packet repair attempts; never unchanged retries. If `retentionReady` is false afterward, stop without commit/push; list remaining fields. Otherwise retain once with `stagingProtocol.retain`, including honest gaps; correction-required is not retention failure or approval. Tool-form refusal: correct form, not judgments.
5. Only `pendingDispositions` allow `/sf-review-decide <phase> --finding <ID> --reason <TEXT>` in a separate human turn; never decide as reviewer. Started as a sub-agent in the author's chat: end with the retained status and findings only; the author follows `continuation` there. Otherwise end with the words `Run this in a new chat:` then `continuation.actions`, target generation/owner; absent: `singularity-flow review-source status <phase> --json`. Never waive, publish, advance or acknowledge amendments for the person.
