# Namespace Code publication evidence

The namespace Engine can publish an initial application-code generation from accepted original
and current source archives, independently approved specifications and plans, and actual pinned
test execution. The same registered `phase.publish`, `phase.submit` and `phase.approve` operations
own the lifecycle effects. Installed Git projects keep their existing execution and authority.

## Supported profile

`sflow-namespace-code-policy/v1` requires enforced specification records, required planned claims,
and a phase whose pinned responsibilities are implementation, verification and optional review.
Scope and planning responsibilities cannot be discharged by this profile. The current source
generation must be the first; earlier Code generations and rework retain their explicit owners.

The shared Code preflight still checks selected paths, source comments, implementation regions,
declarations, planned fulfillment and candidate coverage. Exact declaration witnesses are joined
to actual retained test occurrences using the existing kernel rules. Passing counts do not replace
an executed declaration. Primary test slots with `all` combination are supported; other methods,
supplemental slots and alternative combinations need their verification-contract owner. Human
visual acceptance is not inferred from these test results.

Every repository keeps its own source revisions, tests and observed claims. Repository-qualified
plans supply local projections without borrowing matching paths or test IDs from another repository.

## Immutable evidence and conditional acceptance

A versioned `code-delivery/v1` policy binding accompanies the existing v4 publication envelope.
It points to a manifest and a `sflow-namespace-code-policy-report/v1` report. Those records bind:

- The original publication actor, configuration, generation, draft hash and artifact bytes.
- Accepted source-retention and original-baseline operation records, including their index revisions.
- The original approved specification, plan, repository mappings and review packets.
- Actual check evidence for the same repository selection and application-file inventory.
- Repository-specific observed claims and each planned acceptance test's joined result.

Publication conditionally reads the source result, source index, baseline result and baseline index.
The first profile also conditionally requires no source-control/origin record for this exact draft;
it does not silently drop a retained control interpretation. Such generations need their named
history/origin owner. Check evidence retains its existing conditional reads and fresh source check.
Without configured checks, publication still compares the current source inventory to its retained
archive before accepting a generation.

The operation identity includes the actual source and baseline bindings. Replacing evidence while
preparing publication changes or invalidates that candidate. Failed preparation preserves the draft
and retained recovery state. An accepted retry returns its original receipt without running tests,
restamping time or recording another approval.

## Replay and takeover

Readers reconstruct the candidate from the original immutable records and compare the entire Code
report. They verify the original publication transaction's read conditions. Current draft indexes
can subsequently move without rewriting an earlier accepted proof. The old checkout, private draft
store and source reader are unnecessary for replay; the shared content and original receipts remain
required. Missing bytes, permission errors and deadlines preserve their actual reader failures.

Within one awaited proof traversal, the observer can reuse the verified original Story policy and
accepted immutable lifecycle receipts. Each new snapshot is still checked against that policy.
Mutable source indexes, current source bytes and final lifecycle/authority checks remain fresh.
The scope expires when its callback finishes, failures are not cached, and another traversal reads
its own proof. This is not a timed or backend-global cache.

Submission and human approval obtain fulfilled owners from the recomputed proof. Neither can
waive missing owners by supplying a readiness flag, copying a report or changing its hashes.
Human identity, authority, self-approval policy and the bound review confirmation stay in force.
The Code report is registered as a shared Story document, so review-resource manifests issue a
readable reference rather than a hash with no corresponding document entry.

## Qualification

232 distinct affected Mac cases passed across the integration, regression and installed-consumer
runs; reruns are counted once. The application fixtures use actual independently approved scope and
plans, retained source and executed Node tests on filesystem, SQLite and application stores. They
cover publication, submission, independent approval and shared-only replay after checkout removal.
The repository-qualified case preserves separate evidence, and the document-read case opens the
actual Code report through its issued review resource.

The checks reject altered reports, future schemas, copied proofs, missing source/control read
conditions, mismatched test snapshots and passing counts without declaration identity. Scope tests
verify concurrent reuse, policy checking for each snapshot, explicit failures after scope expiry,
fresh traversal reads, cancellation and recovery after a real permission error. Existing failed,
skipped, ambiguous, shared-origin and stale-result behavior remains covered.

The installed SDK's 33 checks passed with the existing 120-second parent and 60-second child bounds.
They include offline source/provenance replay, actual checks, retained lifecycle receipts and NodeNext
declarations. They do not qualify every application workflow in the packaged host. Source validation,
VS Code types, the unchanged 2,011-site Git ownership audit and all 13 original bundle ceilings passed;
the gateway remains 852/852 modules. Windows, hosted CI, live providers and production installation
were not exercised.

## Host use and remaining work

Bind shared record/content ports, authenticated access, private working storage, actual source
units/readers and the configured SGOS check execution owner. Retain the original source selection
before editing. After authoring the Code generation and summary, use:

```js
await engine.run('phase.source.retain', { workId, phaseId, operationId: 'retain-code-1' });
await engine.run('phase.checks.run', { workId, phaseId, operationId: 'check-code-1' });
await engine.run('phase.publish', { phaseId, authored: 'governed-agent', channel: 'copilot-host' });
```

The checks must have been executed and retained for these exact bytes; publication does not infer
execution from the summary. Submission and an authorized human's confirmed approval are separate
operations.

This is an initial supported application profile. Native history/rework, shared-namespace origins,
test recovery, other declaration adapters, additional acceptance contracts, downstream Code-input
policies, corner-case analysis and finding decisions retain explicit requirements. Constitution,
artifact-set and other configured owners are not waived. Complete cross-agent application journeys,
installed-project migration and final distribution/performance qualification keep Phases 5, 7, 8
and 9 open.
