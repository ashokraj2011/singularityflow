# Namespace source facts for Code publication

The Code preflight rules can now evaluate an accepted namespace generation without a Git commit
or access to its original checkout. This is an internal publication-admission component, used by the
[initial Code publication profile](ENGINE-SDK-NAMESPACE-CODE-PUBLICATION.md). It is not another public
query or a complete application-workflow writer.

## One policy, two observation boundaries

The native entry still requests local exclusions, the exact Git work-interval check and the original
change set. Its success results, finding identities, error order and refusal formatting stay intact.
The namespace entry instead requests an authenticated source-generation basis and delegates to the
same candidate rules. Its versioned `sflow-code-source-basis/v1` names the actual Story, phase,
generation, repository, source selection, generation intent and original/current snapshot revisions.
`baselineCommit` is null. A namespace revision is never presented as a Git commit.

Namespace finding candidates use a distinct identity that includes their exact source basis.
Git finding candidate identities keep their original digest. A basis object is an input identity,
not proof of acceptance: the namespace reader must authenticate the actual original and generation
receipts before serving any source facts.

Required test-tag allocation and the stable aggregation of scanned tags have shared kernel owners.
Native source reading retains its original security checks and legacy prose fallback. Namespace
reading uses actual approved specification and planning records, including repository-qualified
local plan projections. No caller claim map or readiness flag substitutes for those records.

## Retained source reader

The internal reader issues a private invocation context only after verifying accepted original and
current archives, repository selection, generation identity, snapshot hashes and content chunks.
It can read changed files from generation chunks and unchanged files from their exact original
chunks. Missing content, permissions and deadlines preserve the actual reader error. Returned
buffers are private copies; the byte cache and invocation have fixed bounds. Final index checks
reject changed source or origin evidence. Reading never executes tests, writes evidence or records
approval.

The preflight adapter supplies these actual facts to the existing source-safety, candidate-scope,
fulfillment, acceptance-tag, test-declaration, implementation-region and candidate-coverage rules.
It refuses unselected candidate paths rather than claim they were isolated. It authenticates the
snapshot against the source receipt's actual lifecycle state, so a caller cannot weaken policy by
passing the same revision with an edited workflow object.

## Qualification

Mac qualification covers 132 distinct affected tests: 99 core, native and namespace checks plus
33 installed-SDK checks. The native oracle preserves all 33 original preflight outcomes. Actual
filesystem, SQLite and application-store fixtures run the shared candidate policy after removing
the checkout; the repository-qualified case rejects missing source comments in one repository
even when another contains them. Private byte copies, generation identity, original I/O errors,
tampered workflow rejection, and a reviewed test-only generation are exercised. Installed consumers verify the shared allocation
helper with infrastructure imports blocked and compile its NodeNext declarations.

The architecture guards, source validator, VS Code types, unchanged Git ownership audit and all
13 original bundle ceilings passed. Windows, hosted CI, live providers and production installation
were not exercised. This qualification does not establish application-publication readiness.

## Publication integration and remaining owners

This component returns a preflight result. It does not attest successful execution or fulfill every
publication owner. Namespace code history/rework, reviewed test-recovery baselines, exact shared-
namespace test origins, additional declaration languages, corner-case analysis and accepted finding
decisions retain explicit owner requirements where their native callbacks are not yet bound.

The initial integration now conditionally retains the actual Code policy result, binds its exact
source archive and test execution, and replays it for registered publish/submit/approve without the
old checkout. It supports a first-generation profile with primary test contracts. The namespace
writer still requires its complete policy closure: constitution, artifact-set, human acceptance and
other missing owners are not waived. Full application Stories and Phases 5, 7, 8 and 9 remain open.
