<!-- sflow-turn-boundary: approval-only -->
**Approval-only:** An explicit human phase ID confirms only the unchanged packet already reviewed in this conversation. The approval CLI is the sole permitted lifecycle mutation, besides /sf-decide step 14 for the decision list. Never edit repository files, run tests/builds/raw Git, delegate, submit, or begin/author another phase. A failed approval ends this turn.

1. Positional argument selects **PHASE-ID**, never Work ID. Run `singularity-flow choices begin approve <WORK-ID> --fetch --for-agent --json --review-packet`. `reason: approval-holds`: relay `sheet.holds`, all three `act.do` routes; no document reads or confirmation. `terminal-obligations-required`: relay blockers/actions; stop without choices or generic recovery. `decisions-required`: do /sf-decide 11-14 now; never print raw decision commands. Match supplied phase.
2. Other `begun: false`: preserve draft, relay `nextAction`, end turn. Otherwise match `approvalPacket.review`, receipt, `reviewBinding`, artifacts and briefs to `approvalContext`; missing/mismatched bindings stop. Read once.
3. **Review outside chat against the exact binding.** List each artifact/brief's identity, generation/hash and verified Markdown-preview link; binary: metadata/path. Require human review of complete bound documents; never infer it from opened previews. Reuse same-chat human acknowledgement only for an exactly matching non-null `displayBinding` and unchanged `reviewBinding`. New chat, changed/null binding, omissions or truncation require fresh human review. Tool output or summaries are not review. Show current `reviewBinding`; document reuse never reuses approval consent.
4. Show identity/authority, agent, checks/usage, decisions/`owedDecisions`, self-approval warnings and `approvalCheck`/`blockingCommits`. Only holds block; follow routes. Unauthorized: show approval groups (`/sf-approvals`) for an approver's `/sf-inbox`, or `act.do` when nobody is listed; stop.
5. A human `/sf-approve <PHASE-ID>` or exact phase answer **after** complete review of this exact `reviewBinding` is `<TYPED-PHASE>`: do not ask again. Otherwise ask for the exact phase ID to confirm linked-document review and approval; wait. A phase supplied before a new or changed packet review is not its confirmation, even if document bodies match. Run `singularity-flow choices answer <TOKEN> phase-confirmation <TYPED-PHASE> --json`, then `singularity-flow approve <TYPED-PHASE> --work-id <WORK-ID> --fetch --selection-receipt <TOKEN> --for-agent --json` only when `ready: true`. When the packet review's `approvalChecklist` lists articles, ask for one answer per article (satisfied, exception or not-applicable, with a reason for the last two) with the confirmation and add `--article <ID>=<DECISION>` per article, then `--article-reason "<REASON>"` in the same order. From /sf-decide 14, add its `withApproval.flags` (decisions in this commit). Never add `--yes`; the receipt is consumed once. `--for-agent` grants no authority.
6. Refusal: relay, end turn (one routed to `singularity-flow decisions <WORK-ID>`: load /sf-decide steps 11-14 now instead); `PHASE_ALREADY_APPROVED`: offer `/sf-next`. Never `--allow-dirty`. Success: commit/push, authority/self-approval. Relay `contextBoundary` commands in order (`/clear` or `/compact`, then `/sf-next`); `keep`: next turn. The approval CLI advances and activates the next phase when the threshold is met; no second advance. End this turn before next-phase authoring.

TRP: read and follow `singularity-flow explain test-recovery`; returned legal actions only.
