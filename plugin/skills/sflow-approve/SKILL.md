Summaries, links and opened previews are not human review or approval. Never show a person a hash, digest or commit SHA: name the step, its generation, its files. Each action: "<timing> — <label>", then its three separate Markdown bullets, in order: "- Copilot: `<copilotCommand>`", "- Shell: `<command>`", "- VS Code (model-free): `<modelFreeCommand>`". Keep returned routes exact; never apart from their label, on one line or in a table. Missing Copilot: "no verified equivalent"; missing Shell or model-free: "not available for this action". Never invent routes or make more calls for formatting. Run a check only when a returned field or command asks for it; never decide from a step's name, kind or route that it applies. <!-- sflow-turn-boundary: approval-only -->
**Approval-only:** The person's own Yes to "Approve <Step> v<N>?" confirms only the unchanged packet already reviewed in this conversation. The approval CLI is the sole permitted lifecycle mutation, besides /sf-decide step 14 for the decision list. Never edit repository files, run tests/builds/raw Git, delegate, submit, or begin/author another phase. A failed approval ends this turn.

1. Positional argument selects **PHASE-ID**, never Work ID. Run `singularity-flow choices begin approve <WORK-ID> --fetch --for-agent --json --review-packet`. `reason: approval-holds`: relay `sheet.holds`, all three `act.do` routes; no document reads or confirmation. `terminal-obligations-required`: relay blockers/actions; stop without choices or generic recovery. `decisions-required`: do /sf-decide 11-14 now; never print raw decision commands. Match supplied phase.
2. Other `begun: false`: preserve draft, relay `nextAction`, end turn. Otherwise match `approvalPacket.review`, receipt, `reviewBinding`, artifacts and briefs to `approvalContext`; missing/mismatched bindings stop. Read once.
3. **Review outside chat against the exact binding.** List each artifact/brief's name, version and verified Markdown-preview link (no hashes), and those of `approvalPacket.review.approvalCovers` (steps it covers); binary: metadata/path; in VS Code the approval page (5) opens them all. Require human review of complete bound documents; never infer it from opened previews. Reuse same-chat human acknowledgement only for an exactly matching non-null `displayBinding` and unchanged `reviewBinding`. New chat, changed/null binding, omissions or truncation require fresh human review. Tool output or summaries are not review. Name the bound generation; document reuse never reuses approval consent.
4. Show identity/authority, agent, checks/usage, decisions/`owedDecisions`, self-approval warnings and `approvalCheck`/`blockingCommits`. Only holds block; follow routes. Unauthorized: show approval groups (`/sf-approvals`) for an approver's `/sf-inbox`, or `act.do` when nobody is listed; stop.
5. Ask `act.ask.question` ("Approve <Step> v<N>?") exactly with ask_user, its choices "Approve <Step> v<N>" and `Not now`, nothing preselected. In VS Code's own chat never ask: the person approves on the approval page, which `#sflowDecide` with `workId` opens. When `approvalChecklist` lists articles, ask for one answer per article on the same form, with `--article <ID>=<DECISION>` each: satisfied, exception or not-applicable. The last two take a reason: `--article-reason "<REASON>"`, in order. Never answer it yourself; Not now approves nothing, nor does a Yes given before a new or changed packet review: that is not its confirmation. After their Yes, run `act.ask.onYes` as returned, then the filled `next.command` its result returns, only when `ready: true`, adding any article answers. From /sf-decide 14, add its `withApproval.flags` (decisions in this commit). Never add `--yes`; the receipt is consumed once. `--for-agent` grants no authority.
6. Refusal: relay, end turn (one routed to `singularity-flow decisions <WORK-ID>`: load /sf-decide steps 11-14 now instead); `PHASE_ALREADY_APPROVED`: offer `/sf-next`. Never `--allow-dirty`. Success: pushed, authority. Relay `contextBoundary` commands in order (`/clear` or `/compact`, then `/sf-phase`); `keep`: next turn. The approval CLI advances and activates the next phase when the threshold is met; no second advance. Relay `landing` when it ends the Story; never merge. End this turn before next-phase authoring.

TRP: read and follow `singularity-flow explain test-recovery`; returned legal actions only.
