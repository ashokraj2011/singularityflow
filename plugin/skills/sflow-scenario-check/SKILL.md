# Scenario testing/retesting

<!-- sflow-copilot-pause -->
First run `singularity-flow phase enter --compose --for-agent --json` once; it composes context only when admitted. Lookup from current cwd (non-Git allowed). Never search `/Users`, `$HOME` or parents for a repo. Require returned `ready`/`workId`/`repositoryPath`; unavailable: `/sf-session` or `/sf-workspaces`, stop. It checks pause before Git. If `paused`, native Copilot; only offer `/sf-pause off`, never resume implicitly. Otherwise follow `agentGuide.readOrder` once, reuse binding/recovery/clarification/references and delivered inputs; no duplicate lookups. Read `clarification.checkpoint`: missing answers permit questions, not drafting. Missing record is not unanswered: reuse same-binding replies; repair recording. Never ask users to supply questions or slice control instructions. Use `personalization.replyName` literally in replies, never artifacts or approval identity.

<!-- sflow-output-contract: clarification-and-artifact -->
**Output contract:** Author configured artifacts from governed inputs and pinned clarification; publish only after readiness. Approved phase inputs are the earlier steps' outputs and settle what they state: never ask what they answer or search elsewhere for them. Summarize artifacts with verified Markdown-preview links; never paste document bodies, code or diffs into Copilot. For code, list touched paths and observed added/deleted/created line counts; unavailable stays unavailable. Use existing evidence, not extra calls solely for display. Summaries, links and opened previews are not human review or approval. For every next action, honor returned `commandGuidance` in order: Copilot, Shell, VS Code (model-free) using `modelFreeCommand`; if absent, say "not available for this action". Missing Copilot: "no verified equivalent". Never invent routes. On a refusal read `remediationPlan`: run its first read-only step once and follow `context.strategy`; never retry an unchanged condition or edit an earlier phase to clear it. One returned `automatic` plan-hash action (such as `sync`) may run once, then re-enter once. Run a check only when a returned field or command asks for it; never decide from a step's name, kind or route that it applies. A refusal saying a check does not apply to this step is not a blocker: skip it and continue. Act on a result's `act` first: its state, `do` routes and any `ask`. A bounded result lists `omittedFields` with exact line ranges in `agentOutput.path`; read only those you need with your file tool. Never stop because a result is long or was saved to a file.
<!-- sflow-execution-boundary -->
**Boundary:** reuse entry `ready`/`workId`, valid `phaseAgent`; cwd=`repositoryPath`. Honor `mutationContract`. Returned `workItemRoot`/artifact paths only; never `$HOME`.


1. Use entry `authoring`; false `policyVerified`: show `policyReason`, stop. Continue only when `effectiveAuthoringSkill` is `/sf-scenario-check`; else relay its route. `retained-generation`: relay `next`, stop.
2. Review recovery/diffs; stop for protected/unowned edits or human decisions. `successor-preparation-required`: run `successor.preparation.command`, preserve drafts/publications, refresh entry once. Use entry `context.text`, clarification/reference paths; if `not-requested` or stale, rerun it once with `<phase> --work-id <WORK-ID> --compose`. Not admitted: relay blockers/next, stop. Required clarification: ask/record before preparation. Expand only needed missing/truncated inputs. Run `singularity-flow prepare <phase>` unless prepared.
3. Run only the approved scenarios and exact authorized test commands/tool actions. No source/test edits here. Retain tested revision, argv/cwd, environment, exit codes, executed test identities and fresh hashed outputs under CLI-returned artifact paths. Never reuse an old report, skip cases or count zero tests as passing. Missing assertions need a repair request.
4. Playwright optional: returned server ID, host readiness and live `singularity-flow mcp smoke <SERVER-ID> --url <APPROVED-URL>`; retain tool/phase/output with `singularity-flow mcp record <SERVER-ID>`. No foreign policy/origins, fabricated records or secrets. Approved tools retain real reports; MCP screenshots are not structured test receipts.
5. Preparation is not authoring. Use the native file-edit tool for the existing report/Agent brief from observed results; resolve TODOs, preserve managed blocks. Entry `testEvidenceFrom` set: verify that step's Code receipt, rerun approved scenarios. Pass only when every required assertion ran/passed; repair for defects; blocked for unavailable/inconclusive evidence. Record clause results and bounded repair requests; never manufacture a pass at a round limit.
6. Preserve validated context. Run `singularity-flow phase prepublish <phase> --for-agent --json --publish-if-ready` (includes draft-check and recovery); follow owned artifact repairs. Stop for confirmation/protected edits. Code repair belongs to `/sf-scenario-repair`, never this check. Follow returned `repairLoop.protocol` for persistent correction/resume; stop unchanged.
7. Use returned `commands.publish` once when `ready` unless `publishIfReady.published`; absent: relay `commands.next`, stop. Summarize the report with its verified Markdown-preview link, fresh evidence, limitations and exact verdict in the returned submit command's decision vocabulary. Human approval of a failure report authorizes repair, not acceptance; initial no-repair completion also needs human implementation-applicability. Relay each `handoff` with its `copilotCommand` and `command`; never submit or approve.
