# Repeated Code returns across unapproved generations

A reviewer can return Release to Code, review the Code successor, and reject it before approving
it. Both change requests remain open. The old generic Code reader required exactly one open
request and stopped; its targeted-entry lookup could also carry an older clause restriction into
the later complete repair. Typed member returns already had their own historical selection.

The read owner now authenticates every original generic return against its accepted transaction,
submitted packet, human authority and actual target-generation reset. The pure kernel selects
the single return for the actual predecessor generation and retains the earlier identities.
Timestamps and array position cannot choose the current request. Copied requests, duplicate IDs,
future generations and ambiguous returns for one generation are refused. This does not silently
combine competing human scopes.

The latest return controls the repair. An earlier targeted return remains in history, while a
later complete return can use the complete approved plan. Conversely, a current targeted return
retains its own exact restriction. Every Code generation still needs fresh source retention and
actual passing checks. Reading an old request consumes no repair budget and records no approval.

## Versioned evidence

New generic repeated histories use `sflow-namespace-code-history/v10`, with the original source
profile and authenticated earlier-return bindings. Code policy/report v24/v25 cover this history
without repository-local coverage, and v26/v27 retain that coverage. The odd version in each pair
requires the separate human verification contract. Earlier-return evidence is retained alongside
the exact predecessor and latest return.

All Code v1–v23 profile values are captured in a compatibility fixture and remain unchanged.
Existing typed member-return histories retain their own profile and comparison meaning. Native
Git records, hashes, authority and output remain on their existing path; no records are migrated.

a copied older request, clear the obsolete targeted entry, refuse publication before new tests,
publish and independently approve the actual successor, complete Release and replay both returns
after the source checkout is removed. An offline installed consumer independently approves Code
generation 3 in a shared-only process and then replays the original records without source bindings.
Its existing 120-second parent and 60-second child bounds are retained.

architecture guards, real native decision compatibility and the original 34-check installed
