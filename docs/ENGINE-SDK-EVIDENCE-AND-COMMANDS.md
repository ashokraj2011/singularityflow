# Retained evidence and command execution

This is an incremental Phase 5/7 delivery on `codex/engine-sdk-foundation`. It does not move
installed authority or complete either phase. Git records, native CLI JSON, human authority and
existing package deadlines remain unchanged.

## Evidence rules and native compatibility

The kernel owns graph hashing, obligation evaluation, scope staleness, result vocabulary and
completion labels. `@singularity-flow/engine-sdk/evidence` exposes those pure values. Evaluation
requires an explicit observation time; it does not read files, count signed identities, run checks
or approve a phase. Actions contain registered operations and arguments, never rendered commands.

Native adapters still admit counted person-presence records and approvals, supply the clock and
render the original command/message shapes. Fourteen results and graph hashes captured from
`c2ac45434` before extraction remain the independent compatibility oracle. Native evidence matrix,
terminal, risk, applicability and signed-approval journeys exercise the actual compatibility path.
Pure risk values authenticate no decision and provide no waiver by themselves.

## Namespace retained-evidence view

`engine.run('story.evidence', {workId})` reconstructs the read-only
`sflow-namespace-evidence-context/v1` from original accepted publications, approved specification
and plan manifests, actual source and test observations, original submitted packets and human
receipts. It uses the shared evidence reader's real publication verifier rather than validating
the same proof through another independent traversal. Invocation-local proof reuse never replaces
the final fresh Story, configuration authority, reader identity and clarification-index checks.

A private draft is not retained evidence. Generations needing authoring are explicitly excluded.
The view neither opens source folders nor executes tests. Every criterion is joined to its
allocated Code phase's original run, including repository-qualified source and occurrence paths;
a later phase's passing count cannot stand in for an earlier criterion's execution. The three-Code,
two-repository journey survives removal of both source folders and replays from shared records.

The manifest explicitly states that local source was not checked, no terminal decision was made
and no approval was recorded. Missing content, permission errors and timeouts retain their original
error objects and details. Unbound native risk and person-presence collections refuse with their
actual required owners; a raw array cannot become a verified human exception. Verification binary
documents still require an explicit text-extraction owner.

## Actual command execution and replay

SGOS now offers `createNodeCommandExecutionUnit` for compile, lint and other declared non-test
commands. It pins the actual executable, argv, environment, source selection and deadline, and
retains process closure, exit, stdout, stderr and before/after source observations. Its separate
`sflow-local-command-execution/v1` never parses test evidence. TAP-looking stdout is still command
output; `tests` and parsed report stay null. A failed compiler cannot be substituted by passing
tests. Changed source still invalidates the result, so a formatter must execute in check mode or
use a separately authorized source-change operation.

Mixed inventories use check-plan v4 and `sflow-namespace-mixed-checks/v1`, with the actual accepted
Story-command identity and optional confirmed recovery agreement. Existing test execution and
check-plan v1/v2/v3 meanings remain unchanged. Readers recompute the kind, manifest, raw output,
source and report bindings. Test-report units cannot relabel themselves as compilers.

An embedding host can explicitly bind `checks: {mode: 'retained-only'}` and
`repairs: {mode: 'retained-only'}`. These bindings replay genuine accepted receipts without an
executor, private draft or source checkout. They cannot contain an execution owner or start a new
run. A new attempt returns the missing execution binding; omission still leaves that operation
unbound. This is an effect restriction, never a readiness assertion.

its original 120-second parent and 60-second child deadlines.

853-module build failed its existing ceiling and was corrected by the direct leaf imports.

The vocabulary has 87 registered operations, 42 default native bindings and 76 namespace bindings
