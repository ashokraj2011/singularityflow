# Run the application

<!-- sflow-copilot-pause -->
Before any boundary lookup or SFlow action, run `singularity-flow pause status --json` and follow its `data.agentInstruction`. If `data.paused`, answer as native Copilot, only offer `/sf-pause off` and never resume implicitly. This skill is already loaded; never call the skill tool for it. Unless paused, continue below in this turn.

Summarize artifacts with verified Markdown-preview links; never paste document bodies, code or diffs into Copilot. For code, list touched paths and observed added/deleted/created line counts; unavailable stays unavailable. Use existing evidence, not extra calls solely for display. Preserve exact returned routes; never combine them on one line or in a table. Missing Copilot: "no verified equivalent"; missing Shell or model-free: "not available for this action". <!-- sflow-execution-boundary -->
**Boundary:** no Story required; cwd=opened Git root or verified `repositoryPath` from `singularity-flow workspace current --json`; refuse if neither resolves; never search `$HOME`/parents. Use exact CLI-returned paths. `repositoryPath` is command cwd, not a prefix for absolute file paths. Never rebase paths or strip `.git/worktrees`. Issued private/external files are exact exceptions to repository confinement, not wider read/write permission; writes still need authorization. Resolve relative paths only against their declared base. On failure, preserve the path and error; never search or recreate it.
The capability's `application.start` entries say how to start it, as typed run configurations (Spring Boot, npm, FastAPI, …) or a plain command; never guess a dev command.

1. Run `singularity-flow app plan --json` (add `--capability <ID>` only when the person named one). With no start entry, or when the person asks to suggest entries, go to step 6.
2. Pick the start entry named in `$ARGUMENTS` (by `id` or `name`), else the only one, else ask with `ask_user`, showing each entry's `name`, `type` and the chosen environment's `resolved.argv`. Pick the environment named, else the only one listed, else ask which of `environments[].name`, showing each binding `status`. For an environment that is not bound, give the person `singularity-flow env bind <ENV> --stdin` to run in their own terminal, piped from their own secret helper; never ask for, type or pipe a value, and never run `singularity-flow env bind` yourself.
3. To start: run `singularity-flow app start <ID> [--environment <ENV>]` with your terminal tool's background (async) mode so it keeps running, then run `singularity-flow app status --json` until that entry is `ready` or reports its failure, within its `ready.timeoutMs`. Report the URL. To debug, add `--debug` when the entry has a `debug` block without a `refusal`. Report `Debugger listening at 127.0.0.1:<port>` and the attach target: the editor's attach configuration for that runtime, or the pid for dotnet. A `debug.refusal` names what the person installs; show it.
4. To check: `singularity-flow app status --json`. To stop: `singularity-flow app stop <ID>`; it stops only what `singularity-flow app start` recorded. Never kill any other process.
5. Report the entry, environment, URL and state, and the next action (run the tests with `/sf-test`, or stop it).
6. To suggest entries: run `singularity-flow app suggest --json`. Show each suggestion's source file, `start.argv`, per-environment `arguments`, `debug` and `environmentNames` (secrets are names only), and its `notes`. Ask with `ask_user` which to keep and their ids. The file replaces the whole application block: write `applicationDraft` to `draft.applicationFile` with a file-edit tool, keeping its existing entries and `tests` exactly, and removing only the suggested entries the person did not keep. Run `singularity-flow app config preview --application-file <draft.applicationFile> --json`; fix each located error in the draft (its `path` names the field) until it is `valid`. Show the draft and the preview's command lines, and only on the person's confirmation run, with `<URL>` from `singularity-flow capability leads --json`, `singularity-flow capability edit <CAPABILITY> --lead <URL> --application-file <draft.applicationFile> --mode set --json` (for a local map: `singularity-flow capability set <CAPABILITY> --application-file <draft.applicationFile> --json`). Show `environmentsDraft` for the person to propose through `/sf-configuration`; never add a value for a secret.
