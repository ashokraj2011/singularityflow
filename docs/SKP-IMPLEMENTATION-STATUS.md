# SKP implementation status

This tracks implementation of *SPEC-SKP v0.2 — Skill Phases and Bring-Your-Own Workflows*. It is an evidence ledger, not a feature-enable switch. A locally inspected skill is untrusted data; its hash establishes byte identity, not authority or host containment.

| Milestone | Current status | Evidence and boundary |
|---|---|---|
| M0 — compatibility and closed readers | Protective guard and versioned readers implemented; milestone incomplete | Version-2 workflow validation refuses skill-producer fields instead of silently treating them as template phases. Version-3 definitions, version-9 Story records, and version-2 WFA snapshots have registered readers and migrations; old template snapshots retain their version-1 identity. This does not prove every M0 acceptance case. `test/skp-compatibility.test.mjs`, `test/mig-golden.test.mjs`. |
| M1 — inspection and contract compilation | Safe foundations implemented; milestone incomplete | `skill inspect` reads one explicit local directory without Git, network, model, or execution, captures bounded exact bytes, and returns candidate-only findings. A pure compiler checks a purported exact confirmation and lowers a complete contract without writing it. WCA must still prove the human confirmation and candidate-catalog provenance. The current path-based directory scanner is not a native isolation boundary against a malicious concurrent ancestor-directory swap; do not use it as an approved asset writer without closing that race. `test/skp-inspect.test.mjs`, `test/skp-package.test.mjs`, `test/skp-contract.test.mjs`, `test/skp-cli.test.mjs`. |
| M2 — retained Story execution and evidence | Retention and evidence foundations implemented; milestone incomplete | A selected skill phase pins its complete approved package and compiled contract into a version-2 WFA Story snapshot. The accepted reader verifies exact file bytes, package and binding digests, interpretation profile, and configuration commit without consulting a live skill folder or latest name. Exact prior-output input receipts, declared artifact-set membership, output kinds/bytes, publication evidence, and human-approval evidence are checked through the existing lifecycle owners. Configuration proposal/refresh preserves approved package bytes. Skill-phase preparation, generation, publication, submission, and approval remain explicitly refused with `SKP_HOST_ENFORCEMENT_UNAVAILABLE` until M5 qualifies a real host and delivery receipt. Reviewed mid-Story skill adoption with selective invalidation (AC-053) and versioned skill workflow export/import (AC-026, scheduled in M3) remain open; no executable M2 pilot is claimed. `test/skp-snapshot.test.mjs`, `test/skp-inputs.test.mjs`, `test/skp-outputs.test.mjs`, `test/skp-state-lifecycle.test.mjs`. |
| M3 — BYO and mixed-workflow recipes | Not implemented | Resolve producer eligibility, planned-claim roles, code and non-code recipes, and workflow transfer through the existing owners. |
| M4 — guided shared authoring | Not implemented | Depends on WCA's authenticated shared draft, autosave, revision/confirmation, deletion fence, and Show path. A local `skill inspect` result is not a substitute. |
| M5 — host/platform qualification | Not implemented | `src/skp-host-admission.mjs` checks structured operation-bound enforcement evidence but is **not connected to a qualified host adapter** and cannot establish a sandbox itself. Real pre-effect read/write/tool/egress/control/process enforcement and delivery acknowledgement must be tested on supported installed hosts before launch. |
| M6 — pilot/promotion | Not started | Requires actual end-to-end approved Story runs and measured release evidence. |

The phase engine can retain and inspect a versioned skill-backed Story, but no current CLI or Copilot command launches, publishes, or approves an imported skill as a phase. A selected skill is not an execution grant. Do not interpret this status as SKP pilot readiness.

AC-053 remains open. WFA currently seals only revision 1 at Story creation, and the accepted Story reader compares its policy and snapshot reference with the immutable creation commit. The creation finalizer refuses an attempted replacement after acceptance with `WFA_AMENDMENT_UNSUPPORTED`; a newer approved skill is available to future Stories but does not update an existing one. Completing AC-053 requires a reviewed skill-version amendment decision bound to the old Story reference and exact new approved package/contract, a new immutable WFA snapshot revision with parent and genesis lineage, an atomic current-revision selection, and an evidence dependency result that names affected, preserved, and unknown items. Affected approvals and receipts must be staled and revalidated through their existing owners; preserved evidence must retain a verifiable unchanged dependency proof. The accepted reader and recovery path must verify the full revision chain before any amended phase can run.

Next implementation order: complete reviewed skill-version adoption and selective lineage invalidation, then the M3 recipes and versioned transfer, WCA shared-draft confirmation, and a genuinely qualified M5 host adapter. Keep skill execution closed until those paths have executable regression and native-host evidence.
