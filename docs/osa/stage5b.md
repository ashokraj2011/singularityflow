## 2 VS Code's card (stage4.md section 6, section 11)

The card's question is the engine's, as the Copilot CLI card shows it. What VS Code adds is only the page, and two checks before the engine's own:

1. **The page's digest.** The answer carries the digest of the proposal the page showed. An answer for any other proposal, or one already answered "Not now" on this page, keeps nothing and says "This question changed since the page showed it".
2. **The list as it is now.** On "Yes, start it" the card reads `decisions <W> --json` again. If the list cannot be read in this checkout (it holds another Story now), or the proposal waiting is another one, or none waits, nothing is kept and the page says which. Only then is the engine's command run, and the engine checks again (`VERSION_CONSENT_WRONG_TARGET`, `VERSION_OPENING_STALE`); its refusal is shown in its own words.

**A switched Story.** `decisions record <W> --version-consent …` run from a checkout that holds another Story switches the checkout back to `W` and keeps the yes, while `decisions <W> --json` there answers `STORY_NOT_FOUND` (found on an isolated Story, section 5 decision 2). The VS Code card reads first, so it keeps nothing and never switches the person's checkout.

**Never sent, nothing overwritten (REQ-050, REQ-051).** The card runs no chat command, no prefill and no terminal for the version: the yes goes to the engine, and the result goes back to the chat's tool call as its answer (`recorded: ['version-opening']`, the engine's words and its route for the step's confirmation). The tests check that no `workbench.action.chat.*`, prefill or terminal command ran.
