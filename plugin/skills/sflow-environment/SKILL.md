# Inspect environment bindings safely

<!-- sflow-copilot-pause -->
Before any boundary lookup or SFlow action, run `singularity-flow pause status --json` and follow its `data.agentInstruction`. If `data.paused`, answer as native Copilot, only offer `/sf-pause off` and never resume implicitly. This skill is already loaded; never call the skill tool for it. Unless paused, continue below in this turn.

<!-- sflow-output-contract: explicit-selection -->
**Output contract:** Collect every required choice explicitly; never infer or preselect; preserve errors, artifacts, and next actions. Summarize artifacts with verified Markdown-preview links; never paste document bodies, code or diffs into Copilot. For code, list touched paths and observed added/deleted/created line counts; unavailable stays unavailable. Use existing evidence, not extra calls solely for display. Summaries, links and opened previews are not human review or approval. After a blank line, display each next action as three separate Markdown bullets, in order: "- Copilot: `<copilotCommand>`", "- Shell: `<command>`", "- VS Code (model-free): `<modelFreeCommand>`". Preserve exact returned routes; never combine them on one line or in a table. Missing Copilot: "no verified equivalent"; missing Shell or model-free: "not available for this action". Never invent routes or make further calls for formatting.
<!-- sflow-execution-boundary -->
**Boundary:** no Story required; cwd=opened Git root or verified `repositoryPath` from `singularity-flow workspace current --json`; refuse if neither resolves; never search `$HOME`/parents. Use exact CLI-returned paths. `repositoryPath` is command cwd, not a prefix for absolute file paths. Never rebase paths or strip `.git/worktrees`. Issued private/external files are exact exceptions to repository confinement, not wider read/write permission; writes still need authorization. Resolve relative paths only against their declared base. On failure, preserve the path and error; never search or recreate it.

1. Run `singularity-flow env status --json` for readiness or `singularity-flow env audit --json` when audit was requested.
2. Report environment names, bound/partial/unbound status, missing names, declaration digest, opaque binding revision, and fingerprint. Never print values, provider references, environment variables, private-sidecar paths, or raw resolver errors.
3. Never ask the user to paste a secret into Copilot Chat. To bind, give this terminal-only shape: `singularity-flow env bind <environment> --stdin`; explain that a bounded JSON object is read from standard input and the value must not be placed in argv or shell history.
4. Removing a binding is the person's, like binding: the guard refuses it in every turn. When they explicitly ask to remove one and the exact environment is known, give them `singularity-flow env unbind <environment> --json` for their own terminal; it removes only private machine-local state, and the committed declaration is unchanged.
5. `ENVIRONMENT_ISOLATED_RUNNER_REQUIRED` means the capability's `policy.localIntegrationEvidence` is off, so that environment-bound check cannot run here. Preserve that status and say so; offer the capability proposal its refusal names, `/sf-configuration` to propose removing the check's environment mapping as a reviewed change, or `/sf-recover`. Never substitute a developer-local pass or claim gate evidence.
6. Environment files (`application-uat.yml`, `.env.uat`, `appsettings.UAT.json`, …): run `singularity-flow env files [<environment>] --json` and report each file's environment, path, status and location (a path, never contents). For a missing file with a template, run `singularity-flow env files create <environment> <path> --from-template --json` and give the person its location to fill in. Never read, search or edit an environment file, the store or a linked file yourself; the guard refuses it. Using an existing file (`singularity-flow env files link`), a folder per environment (`singularity-flow env files root`), `adopt` and personal files are the person's commands in their own terminal, or VS Code: Singularity Flow: Environment Files.
