# Provider-neutral workflow continuation

`engine.run('story.guide', { workId })` reads the selected lifecycle record and returns
`sflow-workflow-continuation/v1`. The optional `workId` is a canonical logical Story ID.
Native branch/Jira alias resolution is a trusted compatibility-host option; it is not an SDK
input. A read does not compose a model prompt, execute a review, acknowledge an amendment,
prepare an artifact or advance a phase.

The kernel now owns the shared decisions behind:

- amendment acknowledgement and source-review author conflicts;
- retained Convergence publication checks and advancement prerequisites;
- source-review correction, human disposition, stale review and submission handoffs;
- code-generation opening, guarded successor review and authored-draft milestones;
- the guide's archived, pending-decision, approval, generation and handoff priority;
- optional document inspection and reviewed intent-amendment proposals.

The rules use phase structure, accepted responsibilities, pinned policy, generation receipts and
review observations. They do not dispatch on a named specification, implementation or release
phase. Existing native helpers and the registered query share those same rules. No store, Git
process, shell parser, model provider or prompt library is imported by the kernel.

An action contains a semantic `kind`, logical `workId`/`phaseId`, the relevant option, finding or
generation, and explicit human/digest prerequisites where required. The SDK adds `operation`
only for a corresponding entry in its registry:

```json
{
  "kind": "return-phase",
  "workId": "STORY-1",
  "phaseId": "team-review",
  "purpose": "phase-correction",
  "targetPhase": "team-review",
  "requires": ["authorized-human", "explicit-reason"],
  "operation": {
    "id": "phase.reject",
    "inputs": {
      "workId": "STORY-1",
      "phaseId": "team-review",
      "target": "team-review"
    },
    "port": "rejection"
  }
}
```

This is a proposed operation, not an executable approval token. Its host must bind the required
port, obtain missing human inputs and invoke the registered operation, which still performs its
fresh lifecycle, identity, authorization and binding checks. An action with `operation: null`
has a semantic continuation but no extracted SDK execution operation yet. The adapter can show
its existing native route; an SDK consumer must not turn the kind into an invented command or
silently choose another action. Completing those remaining operations is still a Phase 5 gate.

Native wording and safe three-surface command rendering remain in the host. The existing guide,
source-review, phase-handoff and Convergence JSON are preserved, including Convergence
classification metadata. The CLI `guide` command enters `story.guide` and renders the exact
returned plan instead of independently choosing its next action. The first-run walkthrough keeps
its existing isolated-sandbox behavior.

The result sets `authorityGranted`, `finalBindingChecked`, `automaticAdvance` and
`approvalRecorded` to false. A ready review does not clear required successor authoring. A
pending human decision precedes approval or authoring. An acknowledgement hold precedes reviewer
conflict repair. Missing, duplicate, unsafe or unbound Convergence publication records retain
their recovery route. A consumed code receipt retains the guarded successor path. No budget,
approval, scope or evidence waiver is introduced.

Compatibility fixtures capture all six native projections for 31 structural scenarios against
`4425a3be8`. The Convergence fixtures use the actual `convergence-report` contract and were
qualified against an isolated copy of that committed source, not outputs generated by the new
implementation. The tests compare the exact serialized outputs and also exercise semantic plans,
SDK input/port/cancellation failures and source/bundled CLI projection.

This extraction does not complete the broader `nextsteps` planner, independent source-review
record writers, progress/report queries, portable lifecycle backend or authority migration.
Existing Git lifecycle/configuration authority and final mutation checks remain unchanged.

Mac qualification on Node 26.12.0 passed 136 checks across 19 test files, with no failures,
skips or cancellations. This includes the native and bundled guide, all 31 legacy scenarios,
seeded/custom phase handoffs, installed SDK execution with infrastructure imports refused,
registry-derived TypeScript declarations, and real publication/submission/approval journeys.
Source validation passed 3,691 checks; VS Code typechecking, all 13 unchanged bundle budgets and
the Git ownership audit passed. The gateway remains at 852 modules, and the audit retains its
2,011 existing production sites without a new bypass. No Windows, hosted CI or provider run was used.
