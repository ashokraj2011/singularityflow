# Publication dependency inspection

The kernel's phase-admission owner now compiles publication dependency requirements and judges
their observations. The native readiness adapter retains the actual reads, diagnostics and recovery
wording. Prepublish, recovery and final publication still reach that same adapter through their
existing operations. There is no second public publication API or new storage authority.

The compiled worklist covers pending evidence contracts, repair journals, appeals, integrations,
approved inputs, MCP host readiness, grounding, clarification, MCP evidence, design sources and
visual coverage. Optional checks follow pinned structure: recorded appeal fields, the configured
design capture phase and the visual-evidence artifact kind. Phase names do not select behavior.

Every inspection binds its observations to one Story, phase, generation, producer and agent.
Required observations cannot be omitted, replaced with a skip flag, supplied twice or changed after
inspection finishes. A missing required observation is a protocol refusal; an empty list is never
interpreted as a successful unperformed inspection. Numeric provider error codes and existing
default source codes remain intact.

Observation and enforcement remain separate. Clarification is inspected on every producer route
so a valid human answer is retained. Only the existing agent producer rule makes clarification
errors blocking. A stale manual record is not bound, and the original warning explains why. A
phase whose clarification policy allows no record remains allowed through that policy's verified
empty-error result. The new inspector neither invents answers nor creates a new interview gate.

Grounding also retains its existing distinction: actual blocker count determines its hold;
diagnostics alone do not create a new failure. The native owner still reads its existing grounding
projection and passes the same record to clarification verification. Input owners/restoration,
repair quarantine/resume, integration acknowledgement, MCP setup and visual/design recovery keep
their original routes and order.

The kernel produces semantic check identities, codes and status. It has no filesystem, Git,
process, provider, path resolution, command rendering or model prompt. It does not verify an
external service, authenticate a person, execute tests, grant approval or publish a receipt.
Observation freshness, content verification and native failures remain the I/O owners' duties.
In particular, a successful read-only preview is not authority to publish: the transaction still
rereads its dependencies and performs the existing final binding checks.

Before production edits, 26 complete native results and validator read sequences were captured
from `46f90b7d2`. The fixtures cover optional/custom phase structure, compound failures, human and
agent clarification, warnings, MCP/repair/design/visual recovery and existing published generations.
The native observer's ports are isolated with actual module hooks; no unmodeled I/O may run in
those compatibility cases. Separate tests exercise incomplete/mismatched observations, strict
data without getters, error codes, immutable results and infrastructure-free execution.

This advances Phase 5 publication admission and provides a shared worklist for the future portable
host. The underlying prerequisite readers and remaining publication policies still need portable
implementations. Phase 7 production lifecycle ports/headless Stories, Phase 8 verified migration
and Phase 9 distribution/performance qualification remain unfinished. Existing Git authority and
public native result meanings are preserved.
